## Question

在全部 Agent 使用 ACP 且无需兼容旧包格式的前提下，Agent 包、能力包和呈现包分别能贡献什么，哪些责任应由宿主固定提供？

确定本地安装/启停/卸载、依赖及认证检查、版本约束、会话绑定、升级时状态与历史迁移，以及失败后的可读性。不要因统一 ACP 而自动取消已选的能力插件，也不预设旧版通用 Runtime/manifest/SDK。

新版本包升级迁移属于必需能力；旧插件格式兼容已经排除；旧 Aibo 数据迁移承诺另在收口票讨论。三者须分开。

范围依据：F02.6、F19.1–F19.3、F19.7、F20.4–F20.7。

适配器维护范围、独立扩展映射及兼容但未验证组合的接入策略遵循 [Agent 能力承诺](04-agent-capability-contract.md#answer)。本票细化版本声明、交付和升级机制，不重新引入内置/外部执行路径或仅允许已验证版本的限制。

呈现包遵循 [呈现接口决议](05-presentation-interface.md#answer)：每次启用一套用户信任的完整包，共享交互流程，必须覆盖当前必需操作和信息展示。本票定义如何声明并验证兼容范围、升级包私有状态及处理不兼容，不要求用户跨包混搭控件。

卸载与升级须遵循 [历史与引用决议](06-history-reference-authority.md#answer)：宿主已保存历史及仍被引用的版本、关联子任务和附件不随来源插件失效而删除；读取这些内容不应依赖旧插件继续运行。

[会话控制决议](07-session-control-and-delivery.md#answer)要求保留输入/尝试身份、未决结果及授权范围。本票须处理包替换后的连接代际、旧审批/迟到回复和会话凭证，不能因重启插件就自动重发未知输入或宣告旧活动已停止；组合验证须承接 [控制证据研究](14-acp-control-evidence.md#answer)的具体限制。

[持续目标、子 Agent 与后台任务的职责](08-goals-and-background-work.md#answer)已确定原生目标推进及分别控制。升级/停用须处理目标与后台活动、未决控制、父子身份和委托读取凭据；不能通过重建目标或重新投递命令迁移状态。所交付扩展须声明目标动作、定向取消及只读补读的真实条件，保留来源包不可用后的已保存历史。

### 三类包与宿主的职责

| 角色 | 可以贡献什么 | 宿主仍承担什么 |
| --- | --- | --- |
| Agent 包 | ACP 启动入口及所需适配、运行依赖/认证检查说明、接入所需配置、可选厂商扩展映射，以及其私有恢复状态的版本转换 | Aibo 会话身份、标准 ACP 处理、会话控制与投递证据、权限/信任判断、历史与引用；包不创建另一条宿主原生协议路径 |
| 能力包 | 无界面的工具实现或上下文提供者，以及使用它们需要的描述、参数、结果和必要配置 | 贡献注册、作用范围与调用校验、活动跟踪、统一输入流程及结果保存；包不能覆盖核心会话控制或引用授权 |
| 呈现包 | 完整工作台布局、控件和业务视图；包内可自行组织框架及模块 | 共享无界面交互、共同状态与操作接口、核心操作授权及故障恢复；不以包私有业务流程替换共同合同 |

这些是贡献角色与接口责任，不预设三套插件 Runtime、每包一个进程，或旧版 manifest/SDK。具体包文件格式、执行语言和装载方式由后续模块架构票选择；三类贡献不能借打包方式绕过各自的生命周期和兼容条件。

Agent 包可交付适配器或声明所需外部程序；外部 Agent 的实际版本、认证和原生数据不因包安装成功就变成宿主管理状态。标准 ACP 由共享模块负责，厂商扩展解释集中于独立映射；包的声明不能替代实际能力协商。模型、推理、Fast、模式等会话选项继续使用已确认的共同语义，不能用包内静态选项覆盖 Agent 报告的实际值。

能力包的工具入口可复用既有 MCP 接线，经 ACP 会话配置交给支持该能力的 Agent；具体桥接、传输及接口格式由模块架构票细化。工具调用须绑定实际接收会话、工作区及有效包实例，不能由模型自报身份取得授权。Agent 不支持所需工具通道时说明原因，不通过宿主直连厂商 SDK 绕过全部 ACP 的要求。包身份/生命周期与 MCP 配置不是同一概念，核心会话引用工具仍由宿主固定提供。

用户选取上下文走共享输入流程：能力包返回共同格式的文本、托管内容或明确的路径引用，宿主展示来源、处理获取中/失败/取消状态，并在用户选择后加入草稿。已取得正文和托管内容保持固定，直接工作区路径遵循既定按路径读取规则；不在排队或发送时静默重新查询并替换所选内容。提供者不可用时，已经保存的草稿内容和历史仍可读取。

能力包不提供任意框架控件插入工作台，也不增加独立面板。呈现包通过共同描述和通用交互展示工具能力、上下文选择、必要配置、错误和禁用原因；首版两条使用路径均须有真实可用的能力包验证，不能仅安装一个空清单就算完成 F19.1。

### 安装、启用与可用性

宿主分别记录包是否已安装、哪个版本启用、当前运行实例、实际贡献可用性及已有会话绑定。启用允许使用该包，不等于已启动 Agent、恢复目标、发送消息或批准工具操作；单一启用版本也不限制同一包服务多个会话。

本地包至少需要可识别的包/贡献身份、版本与内容身份、宿主接口兼容要求、目标平台和运行依赖，以及适用的私有状态版本。名称相同不等于身份或恢复合同相同。身份、内容和接口不兼容的替换须按变更处理，不能借沿用版本号原地覆盖当前运行内容。

安装/启用检查覆盖 F02.6 所需的可执行程序、必要依赖及认证可用状态。检测说明缺少什么、当前能确认什么，以及用户如何使用原生登录或安装入口完成准备；没有可靠检查路径时显示未知，不因探测而创建/恢复用户原生会话、接受审批或执行工作。探测代码同样遵守可信扩展合同，可信代码模型不等于进程沙箱。

本票不将上述检查扩展为自动下载 Agent/运行时、在线分发、统一原生账户管理中心或任意跨包调用总线。包所需实现依赖可以随本地交付准备；缺少必需条件时给出可定位错误，不偷偷改动用户外部环境。具体启动配置与必要输入可使用共同表单，不因此恢复未选的完整 Agent 设置中心。

沿用兼容但未验证组合可接入、正式支持绑定已验证组合的决定。区分包接口兼容、当前运行条件满足、原生恢复是否已核实，以及正式测试覆盖；任何一项都不能代替其他项。已知不兼容阻止使用或升级，未知不能伪称已验证，也不能把已知失败改标未知来绕过 Q56。

### 会话绑定与变更生效

Aibo 会话持有稳定身份，绑定其 Agent 接入来源、原生会话身份及版本化恢复依据。能力贡献的实际使用关系也由宿主记录，供判断变更影响；它们不转移业务历史所有权。记录上次使用的版本用于检查和转换，不表示旧版本可永久并行运行。

变更范围按实际关联确定，包括受影响的会话、目标、子 Agent、后台任务、工具调用、上下文获取和相关连接。已公布工具或接入能力包的存活会话也属于影响范围，不能只统计恰好正在调用的瞬间。当前 prompt 空闲不证明相关活动全部结束；启用中的持续目标仍可能继续推进，须按已有控制规则核实。停止请求、停止确认与无法判断的状态分开，不能因用户点击卸载就显示已停止。

影响执行的升级、停用及卸载须与会话控制协调。候选准备与等待期间，旧活动仍按原合同运行；进入变更生效阶段前关闭新的受影响使用入口，保留待发送输入及已有暂停原因。当前活动按用户选择等待或明确停止，不用阻断其正常工具调用来冒充已经停妥。未知状态影响能否确认静止时先核对；已确认无活动但旧输入消费结果仍未知时，保留该事实，不通过升级消除记录或补发输入。

确认可以变更后，失效或释放旧实例/连接和凭据，再使新版或停用/卸载状态生效。旧审批、迟到结果和已缓存工具信息不能被套到新实例；必要重连或配置更新须遵循恢复合同。没有经验证的更新路径时，不对存活会话热换工具实现或协议解释器。未受影响的包和会话不因此被整体停止。

升级、重新启用、重新安装均不自动恢复队列、目标或原生会话。旧队列、草稿、设置和必要恢复事实保留，由用户明确继续；解除安装变更的门控本身不是新的执行授权。工作区信任撤销仍立即生效，不能以等待卸载或升级结束为由继续授予宿主访问。

### 升级与关联会话迁移

一次包升级按以下责任完成，具体存储事务和文件组织由后续持久数据及模块架构票选择：

1. **准备候选。** 保存本地新包的独立候选，不覆盖当前启用内容；核对身份、接口、依赖、可读取的状态版本和关联范围。检查后若又出现新会话或调用，生效前须重新核对。
2. **确认运行可变更。** 按 Q55 等待或明确停止相关活动并处理旧连接；不恢复候选原生会话来试探是否可停止。
3. **在副本上转换宿主管理状态。** 包可转换自己负责的版本化配置/恢复描述/私有状态，宿主验证结果及绑定不变量；原材料在生效前保留。转换接口读取原状态并产生候选结果，不连接/恢复原生会话或调用业务操作；它不是任意升级脚本。包迁移不重写共享历史、固定引用、投递证据或其他包的数据。
4. **统一激活。** 必需检查及转换成功后，切换启用版本和相应状态/绑定。归档不成为丢弃恢复依据或跳过必要转换的理由；不能照搬旧实现把不兼容归档会话自动变为永久只读。
5. **保留明确结果。** 记录版本、宿主状态是否生效及原生恢复仍待核实的部分；清理候选或旧程序的条件由数据保留规则决定。激活成功不等于所有旧会话已经在原生 Agent 中恢复成功。

迁移保持 Aibo 会话及其原生执行上下文的归属，不把跨 Agent 转换、创建全新原生会话或重发旧输入伪称原地恢复。尚未建立原生绑定的会话也要保留草稿与投递事实；不能仅因缺少原生 ID 就推断旧操作从未发生。

新版生效前的已知不兼容、必要转换失败或不完整结果，默认阻止整次升级；保留旧版与宿主管理原数据，不留下默认“部分会话迁移成功、其余永久只读”的结果。这个承诺限于宿主实际控制的准备和转换，不包括恢复 Agent 外部数据库、配置或已经执行的工具副作用。

原生恢复不作为无提示的升级探针。若某种兼容性只有启动/恢复后才可核实，明确保留未验证事实，待用户实际继续时核实。随后发生原生恢复失败时，显示该会话不可恢复的具体原因，保留历史、草稿、恢复材料及未知结果；不自动新建替代会话，不宣称本地副本能回滚外部变化，也不因此承诺未选的任意撤销/降级功能。

包变更有可持久核对的操作结果：中断后能判断哪个包和哪些宿主状态已经生效。应用重启可完成可验证的本地收尾或恢复未生效前的状态；不能为了判断事务结果而启动原生 Agent。重复恢复本地变更不能再次执行迁移副作用、原生命令或业务输入。

### 停用、卸载与重装

停用保留包与数据，阻止后续使用；卸载移除程序及安装可用性，保留已保存业务历史、引用、草稿和仍承担恢复/未决责任的数据。保留的材料不继续授予包、Agent 或旧连接访问权限。用户的外部 Agent 安装、认证与原生存储不由包卸载顺便清理。

Q58 要求卸载后的恢复可能性独立于包程序是否还在。必要私有恢复材料不能只放在会被无条件删除的程序目录；宿主需保留其归属及解释版本。重装时核对包/贡献身份、状态格式、原生来源及兼容条件，成功后提供明确恢复入口；显示名相同或包重新出现不能自动重绑定、授权或续跑。

原生数据已经丢失、外部版本不兼容或必要状态无法转换时，仍可阅读宿主历史，并明确说明实际恢复限制。保留恢复可能性不保证外部数据可恢复；也不要求永久保存所有旧程序、原包、缓存及重复私有副本，其回收条件由持久数据票确定。

### 呈现包的特别规则

呈现包沿用单一完整界面、共享无界面交互和共同业务接口，不受“更换执行包需先结束 Agent 活动”误伤。替换、升级或回退呈现可以重建整套 UI，Agent 执行与宿主历史仍由原控制模块持有；默认包和外部包使用同一合同。

装载前核对呈现接口兼容范围及必需流程覆盖，私有状态在副本上转换；共同状态由宿主恢复，不能把包私有布局迁移等同于全部工作状态迁移。包内声明需要由兼容检查和契约验收支持，不能仅凭自报覆盖就认定合格。

加载失败、不兼容或确认崩溃按既定规则回退默认呈现；持续无响应使用独立恢复入口。回退保留共同状态及可恢复的私有原材料，不强制放弃草稿，也不因关闭或卸载呈现而取消 Agent。当前外部呈现停用/卸载时切回默认界面，内置默认呈现必须持续可用。

### 逻辑接口与验收

包管理集中承担以下职责，避免各呈现包自己执行安装迁移或控制原生运行：

| 接口职责 | 对调用方的承诺 |
| --- | --- |
| 准备本地包、检查可用条件 | 返回包/贡献身份、兼容结果、缺少条件与可确认范围；准备不等于启用或执行 |
| 查询变更影响、请求启停/替换/卸载 | 复核实际关联与活动，提供稳定操作身份和阶段结果；不把停止请求当已完成 |
| 转换及激活包私有状态 | 限定状态范围、保留原材料，必要转换整体成功后才生效；中断可核对 |
| 注册工具/上下文贡献 | 提供共同的无界面描述与调用合同，交给宿主执行授权、活动管理及输入流程 |
| 核对重装后的绑定 | 匹配来源及恢复依据，报告可尝试、缺失或不兼容；不自动启动工作 |
| 加载与恢复呈现 | 复用共同状态和完整流程校验，按既定规则回退，不改变执行所有权 |

| 验收场景 | 必须证明的结果 |
| --- | --- |
| 本地安装 Agent、工具能力包、上下文能力包及完整呈现包 | 各自贡献真实可用；缺依赖、认证或接口不兼容有明确原因，安装不自动执行会话 |
| Agent 调用工具与用户选上下文 | 两条路径可用，授权/来源正确，选入草稿不自动发送；不同呈现框架复用同一流程 |
| 工具或上下文来源包不可用/卸载 | 已保存结果、草稿、历史及固定引用仍可阅读，不依赖旧包渲染或重新查询 |
| 活动目标、子任务、上下文获取或未决停止期间变更 | 只准备候选或等待处理，不宣称已切换/卸载，不产生同包新旧版本并行服务 |
| 兼容检查或任一必要宿主状态转换失败 | 新版不生效，旧版和原材料保留；归档会话不被静默丢弃恢复资格 |
| 升级前检查及副本迁移 | 不启动原生恢复、目标或工具工作，未知原生兼容性不伪称已验证 |
| 统一生效前后崩溃或重复恢复操作 | 能判定有效版本和数据，无半套绑定、重复迁移副作用或自动重发输入 |
| 旧实例审批、工具请求或结果迟到 | 不能取得新实例权限或修改新绑定；仍可按来源保存必要未决事实 |
| 卸载、重装兼容包后明确恢复 | 保留宿主身份和历史；真实恢复成功或失败均有证据，不自动续跑或新建替代会话 |
| 呈现升级失败、当前呈现卸载或卡住 | 共同工作状态保留，按规则回到默认界面，Agent 执行不被连带停止 |
| 外部 Agent 自行升级或原生数据改变 | 重新核对实际条件，显示兼容/未验证/失败状态，不声称宿主可回滚外部变化 |

依据 [现有插件职责与升级边界的事实基线](16-package-lifecycle-evidence.md#answer)，旧实现的候选 resume 校验、永久只读卸载和有限撤销机制均未直接继承。本票定义新合同，不以旧源码存在当作新版本已经验收。

- [持久数据、搜索与诊断的所有权](10-data-ownership-and-search.md)：确定包操作记录、有效版本与宿主状态切换的事务、私有恢复材料、失败副本及旧程序的保留/回收；保留必要材料不等于保留全部原包。
- [模块接口、技术栈与桌面部署形态](11-module-and-desktop-architecture.md)：具体化本地交付格式、版本化贡献接口、扩展代码装载/故障处理、MCP 接线及凭据、必要检查入口；不以旧通用 Runtime 为前提，也不引入原生 Agent 旁路。
- [跨框架替换与呈现故障回退的最小原型](13-presentation-conformance-prototype.md)：可用模拟能力贡献验证统一上下文选择和呈现失效处理；这不替代真实包安装、原生恢复与工具授权验收。
- [架构验收与旧版切换的承诺](12-architecture-acceptance-and-transition.md)：按实际 Agent/适配器/原生版本及两个目标 OS 验证上述链路。旧格式插件直接兼容已排除；旧 Aibo 数据迁移范围仍在该票决定，不与新包升级迁移混为一项。

本票完成包职责与生命周期决议，未实现包管理逻辑、执行真实安装迁移或验证原生恢复。
