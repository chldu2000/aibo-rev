## Question

呈现包应获得什么数据、发出什么操作，哪些交互与阅读状态由共享模块持有，哪些属于一次视图实例？怎样让完整工作台替换框架而无需修改内核？

讨论布局/控件/业务视图的定制边界、独立构建与加载、版本协商、事件订阅和释放、长会话增量更新、焦点/选区恢复、国际化，以及呈现失效后的默认 UI 回退。区分功能隔离、权限隔离与进程崩溃隔离。

默认 UI 可选任意框架，但组件类型、框架响应式对象与生命周期不能成为共享接口前提。至少以两种不同框架的完整关键流程验证，而非只换一个按钮。是否需要原型、验证哪些不确定性由本票提出后续票。

范围依据：F04–F06、F20–F21、F25。

前置约束见 [生命周期决议](03-runtime-lifecycle.md#answer)。是否采用标签页及提供关闭入口仍由本票讨论；不能把“关闭会话”当作已确定的必备操作。

共同能力模型、扩展映射职责和缺失核心功能的禁用入口遵循 [Agent 能力承诺](04-agent-capability-contract.md#answer)；本票细化呈现接口，不在各 UI 框架内重新解释厂商协议。

### 模块职责与状态归属

这里的共享是职责与接口要求，不意味着所有状态放在一个进程或一张数据库表中。

| 所属模块 | 内容与责任 | 呈现侧关系 |
| --- | --- | --- |
| 运行核心 | 提供 Aibo 会话与业务历史的读取入口；持有 Agent 能力、活动执行、权限请求、投递结果及恢复事实；处理标准 ACP 与扩展映射后的共同语义 | 提供可读取的业务模型与受校验操作；UI 不自行解释厂商协议或判定执行成功 |
| 共享无界面交互模块 | 草稿编辑、附件/引用选择、审批/追问的作答状态、提交进度、错误与重试入口；协调共通呈现状态恢复 | 默认包与外部包复用同一流程；与框架组件、store、hook 和路由实现无关 |
| 当前呈现包 | 布局、控件、排版、局部键盘/指针交互、动画与瞬时界面状态；将语义位置映射到实际控件 | 消费共同数据并发出操作意图；可定制审批、追问及确认界面的外观，但不改变请求选项含义和业务确认规则 |
| 桌面宿主 | 窗口与呈现实例的管理、恢复入口、文件选择/剪贴板/资源访问等必要原生能力的桥接 | 不依赖失效的呈现实例来发起恢复；具体部署及原生接口由后续选型决定 |

这里确定业务读取入口位于呈现之外，不提前决定原始 transcript 与业务历史的权威来源或具体持久模块；这些仍由历史与数据决议确定。

运行核心持有待处理审批请求及其真实结果；共享交互模块持有用户正在填写的回答及呈现所需状态。两者不可混为“某个组件里保存的待确认对象”。用户尚未提交的输入也不能因重挂载而被自动提交。

默认界面与外部包使用同一套公开呈现接口；默认 UI 不能依靠外部包拿不到的业务私有入口来完成核心流程。跨框架适配只处理该框架的订阅与渲染衔接，不重新实现业务交互状态机。2026-11-04 用户明确正式版本暂不指定设计系统或呈现风格，原先由 F20.1 带入的 Material 3 要求撤销，内置默认呈现仍保留。

共通呈现状态以会话、消息/工具条目及语义字段等稳定身份定位，不能用 DOM 节点或组件实例作为持久身份。可对应的焦点、选区、展开和阅读位置在换包后恢复；新布局没有对应位置时保留原记录，选择可用的语义位置，不伪称精确复现。包私有呈现状态单独保存，不能覆盖另一包的布局。

### 共享呈现接口的约束

以下是接口必须承担的职责；具体方法名、序列化格式与传输方式留给后续规格，不直接采用任何框架或桌面容器的对象模型。

| 接口方面 | 必须具备的语义 |
| --- | --- |
| 查询与读取 | 提供工作区/会话目录、结构化会话内容、共同能力状态及禁用原因、待处理请求等视图所需数据；长历史支持分段读取和按稳定身份定位，不要求每次全量装入 |
| 交互与业务操作 | 接受明确目标的操作意图，返回可辨识的受理、完成或失败状态；运行核心校验实际能力、当前状态和授权。重载 UI 不自动重发未决操作；具体投递与审批不变量由会话控制票定义 |
| 状态快照与持续更新 | 新实例能取得一致快照并继续接收有序更新；可识别版本/游标缺口并重新同步。允许批量刷新，不能丢失业务内容或待处理请求，也不要求逐个协议分片触发渲染 |
| 实例装载与释放 | 明确兼容检查、装载、就绪、订阅、失联和释放；实例具有可区分的身份，旧实例的迟到操作不能冒充新实例。释放订阅和呈现资源不等于取消 Agent 执行 |
| 状态保存与恢复 | 共通状态不得只存在于呈现包实例；共享层确认保存并供重挂载读取。包私有状态按包和适用对象区分；具体存储与保留策略由数据所有权票定义 |
| 原生交互与资源 | 文件选择、图片剪贴板、拖放所需资源及打开本地目标等通过明确桥接提供；业务操作仍由宿主校验。这里只承诺必要能力，不把任意原生命令通道当作通用呈现接口 |

跨模块数据合同须可序列化，不能要求外部包导入默认 UI 的组件类型、响应式代理、闭包或路由。包内部可自行使用框架和 DOM；局部装载所需的平台对象不应渗入共同业务数据合同。是否采用同文档装载、独立文档或原生视图，由后续原型与部署决议选择。

语言、主题偏好及操作确认偏好通过共同语义传递；呈现包负责其文本和视觉实现，并满足已选的中英文、跟随系统语言和状态持久化要求。键盘、焦点、选区、中文 IME、弹层及图片输入必须验证实际行为，不能仅凭接口类型正确认定兼容。

### 回退与完整性验收

- 兼容检查应覆盖必需交互的支持范围；声明支持还须有实际流程验证。完整包须让所选功能可达，但不要求与默认界面逐控件对应。
- Agent 缺少能力时仍显示禁用入口及原因，这是合法的 Agent 差异；呈现包缺少该核心流程的表示或操作方式，是呈现完整性缺口。两者不能混淆。
- 面对无法专门呈现的可读内容，可采用保留信息的通用视图；无法正确处理必需的交互时不能假装成功或静默忽略，应按不兼容处理。
- 明确失败回退到默认呈现时，重新连接已有运行和共通状态，不重建业务会话或重新发送输入。默认呈现自身若失败，应保留宿主恢复与诊断入口，避免无限回退循环。
- 无响应时的手动恢复入口必须在失效 UI 之外可达。进入恢复后可以重建整套呈现，不承诺只替换某个卡死控件；不能依赖卡死界面配合卸载。
- 可信前端代码不取消故障隔离要求。同文档、独立文档或多视图等候选是否能覆盖故障场景，必须在目标系统上验证；本票不依据研究文档宣称任何机制已通过。

### 2026-11-10 补充：默认工作台设计带来的完整性要求

依据用户 2026-11-10 对[默认工作台界面方案](../../../docs/design/ui-interaction.md)的确认，Q25 的“完整呈现包须覆盖全部必需的用户操作和信息展示”具体包括以下内容。外部呈现包可以换用其他形式和位置，但不能省略：

- **当前会话的后台状态**：待处理审批/追问、持续目标、子 Agent、后台任务与消息队列，须在会话视图中随时可见，且保留与默认界面相同的状态区分（推进中、已暂停、请求未确认、结果未知等），并可进入各自的操作与详情。默认界面以输入框上方的状态条实现。
- **工具面板的承载位置**：须为已启用能力包贡献的工具面板提供承载位置与打开/收起入口（依据 [09 修订](09-package-lifecycle.md#2026-11-10-修订能力包的工具面板)）。缺少承载位置按不兼容处理并回退默认界面。
- **会话详情**：引用授权状态、用量、适配器与原生会话信息可以默认隐藏，但须有可达入口。

兼容检查与实际流程验证同样覆盖上述三项；仅声明支持不算通过。

### 2026-11-11 修订：默认界面改用原生 UI，取消外部完整呈现包

依据用户 2026-11-11 的 Q112–Q113（[ADR 0006](../../../docs/adr/0006-native-ui.md)），默认界面改用 MyGO 原生 UI（Go），**不再提供可替换的外部完整呈现包**（F20.4–F20.7 取消勾选）。本决议据此修订：

- **不再成立：** Q19 的“每次启用一套完整呈现包”、Q22 的跨包恢复、Q24 的自动回退默认界面与独立手动恢复入口、Q25 对外部包的完整性门槛与兼容检查，以及“默认界面与外部包使用同一套公开呈现接口”“框架中立”的要求。2026-11-10 补充中对“外部呈现包”的要求随之失效；三项内容本身（后台状态展示、工具面板承载位置、会话详情入口）仍是默认界面的要求（UI-STRIP、UI-NAV-04/05）。
- **继续成立：** 模块职责与状态归属（运行核心 / 共享无界面交互模块 / 界面 / 桌面宿主）；共通呈现状态不得只存在于界面组件中，重建界面或重启后可恢复；审批请求的真实结果由运行核心持有，作答状态由交互层持有；Q23 的默认导航；界面不自行解释厂商协议或判定执行成功。
- **故障：** 原生界面与运行核心在同一进程，界面故障的处理见 ADR 0006“后果”。能力包的工具面板仍是独立的网页，在独立进程中运行，按 ADR 0005 §5（2026-11-11 修订）处理故障。
