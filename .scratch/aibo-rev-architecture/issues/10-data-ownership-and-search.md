## Question

每类持久数据由哪个模块拥有、为何保存、谁可修改、何时可回收；怎样避免同一内容被多份永久原包与投影重复保存？

覆盖业务历史、附件与引用版本、草稿/阅读状态、队列与投递证据、恢复状态、授权事实、包状态、诊断日志及可重建索引。确定事务和版本演进需要保证的边界，以及中断/损坏时的恢复责任。

搜索须覆盖已选的消息、工作区文件名/路径/文本、命令/Skills、设置与插件；文件搜索不要求先实现文件浏览器。讨论用量目标和保留预算，但不自动加入未选中的数据管理 GUI 或清理产品功能。

[会话控制决议](07-session-control-and-delivery.md#answer)要求在外部投递前保存必要的输入与尝试证据，并区分本地受理、可能送达及已确认阶段。本票确定持久与事务边界、宿主命令去重、确认配置/审批/读取授权及未决结果的保存和回收；物理清理不能把未知结果改写成未发送。

[Agent 包、能力包与呈现包的生命周期](09-package-lifecycle.md#answer)已确定单一启用版本、必要状态副本转换及卸载后保留恢复可能。本票定义包操作结果与有效版本/绑定的事务、候选副本和旧程序的回收、包私有恢复材料的保护，以及工具/上下文结果进入草稿和历史后的保留；不把所有原包永久保存，也不随程序卸载删除仍被引用或仍用于恢复的数据。原生外部数据不在宿主升级回退保证内。

### 数据所有权

每类权威数据有明确的逻辑写入责任；其他模块通过其接口读取或提出操作，不由 GUI、Agent 包和索引各自改同一事实。模块职责不要求每类数据一个数据库或进程，也不要求把已有表结构搬入新项目。

| 数据 | 逻辑所有者与写入依据 | 保留及派生规则 |
| --- | --- | --- |
| 工作区、Aibo 会话身份及目录状态 | 工作区/会话管理依据用户操作维护 | 归档、移除目录入口和卸载包不删除已保存历史的归属 |
| 消息原文、工具记录、已保存子历史及任务输出 | 历史模块接收标准/扩展转换后的可观察内容与明确来源关系 | 是阅读、搜索和引用的依据；完成内容不被原生重放或压缩静默替换 |
| 托管附件与正文内容对象 | 内容存储接受取得并确认保存的字节 | 不可变内容可被多个记录/版本复用，生命期由所有保留关系共同决定 |
| 引用历史版本与成员范围 | 引用模块在用户加入/明确刷新时固定已保存范围 | 使用固定内容及关系，不逐次复制整个历史树；与读取授权分开 |
| 草稿、选中附件/引用及共通阅读状态 | 共享无界面交互模块按用户编辑和状态确认维护 | 跨呈现恢复；进入队列/发送前固化所用内容，界面销毁不承担保存责任 |
| 输入、队列、投递尝试、确认配置及未决操作 | 会话控制模块按意图和实际证据维护 | 关键事实先保存后外部投递；未知结果不能按日志过期删除或改写成未发送 |
| 信任、授权决定、引用读取范围及必要审计事实 | 宿主授权/控制模块按有效身份、范围及用户选择维护 | 保存必要身份、目标、决定、结果和因果关系；不依赖完整协议原包作为唯一依据 |
| 目标、子 Agent 与后台任务关系/状态 | 运行控制模块依据可验证的原生身份和状态更新维护 | 最新状态、重要结果及停止证据分开；正文仍由历史模块保存，无变化快照不重复永久存储 |
| 原生会话绑定与恢复材料 | 会话绑定及包生命周期模块持有，Agent 包解释其私有格式 | 保留所需来源和版本；卸载后仍可用于明确重装恢复，不等于备份整个原生会话库 |
| 包版本、候选、变更记录及包私有状态 | 包管理协调有限范围的状态转换及统一生效 | 原材料、候选及旧程序按恢复/未决责任判断；不把整个程序目录都视为必须永久保留 |
| 搜索索引与定位表示 | 搜索模块从权威内容或明确来源生成 | 可重建，记录来源版本/进度，不作为历史正文或引用身份的权威 |
| 文件搜索信息 | 文件搜索模块依据所选工作区的当前磁盘内容产生 | 文件变化后失效或重建；不以永久保存整仓库正文副本为前提 |
| 命令、Skills、设置及插件搜索目录 | 各自注册/发现模块提供，搜索模块维护派生目录 | 明确当前、缓存或不可用状态；不为搜索静默启动 Agent 或执行项目代码 |
| 诊断日志与可丢弃过程明细 | 诊断模块接收受控字段；过程生产者负责区分必要事实 | 日志按独立预算轮转，过程表达只有在必要内容/事实另有可靠保存后才可丢弃 |

Agent 包与能力包可以提供版本化私有状态及转换结果，不能直接迁移共享历史、引用或其他包的数据。呈现包使用共同查询和操作接口，不持有独立的权威会话库。用户项目文件、外部 Agent 的会话库、认证和原生日志仍属于外部来源，不进入宿主自动清理范围。

### 保存、发布与减少重复表达

接入模块可在有界缓冲中合并增量，历史模块形成稳定记录、顺序、内容范围和来源证据，可靠提交后才向共同状态/GUI 发布新的正文版本。原文内容保持不变，允许合并分片及归一化格式；小批次不等于每个 token 重写一份整条消息或永久保存一次完整快照。

读取和固定引用只使用已提交内容。若进程在接收之后、提交之前中断，该部分不能被标为已保存；恢复时按中断或已知缺口处理。一次回合完成、工具成功或历史完整等业务状态，需要与支撑它的必要内容/事实一致地提交，不能先发布“完成”再丢失最后一段内容。

流式过程、当前投影、引用版本和派生索引可以使用同一内容来源。正在生成的记录可以更新；已被引用的旧范围或版本必须保持可读。合并旧分片、重排物理文件或转换存储格式，只能在证明原文及固定范围等价后释放原表示，不能破坏引用或把修订后的内容套回旧版本。

重放/补读去重依据来源身份、语义版本和可验证的内容范围，不用“文本相同”合并两次不同用户输入或工具调用。相同字节可在物理内容层复用，但两次发生的业务记录及授权关系仍然独立；内容标识相同不授予跨会话或跨工作区访问。

默认不另建一套永久完整 ACP 包档案。原包仍是业务内容、关联、恢复或未决证据的唯一载体时，先提取并可靠保存所需事实，未完成前不得按诊断明细淘汰。未知业务内容不能仅因当前解释器不认识就丢入短期日志；须保存可读原文/通用表示及来源，并说明未解释范围。

草稿和阅读状态可合并自动保存，区别当前编辑值与已保存版本；不把每次键盘输入宣称为已经持久化。切换/重载使用共享状态，发送或入队前必须确认所用正文、附件与引用已保存。草稿转为队列项须同时转移保留关系，不能在两者之间出现内容暂时无主、可能被清理的间隙。

### 事务、恢复与必要事实

以下是必须成立的逻辑原子性，不预设具体数据库事务写法：

| 操作 | 必须一起成立的事实 |
| --- | --- |
| 提交历史内容 | 内容及其稳定身份/顺序/完整性、可发布版本与派生更新依据一致 |
| 接纳附件或固定引用 | 对应字节/内容范围确已可靠保存，拥有者和版本关系存在；不能引用只在临时文件中的未完成内容 |
| 草稿入队及准备投递 | 输入、托管内容、固定引用和队列/尝试身份一致；必要证据在外部调用前保存 |
| 启用引用读取 | 接收会话、版本/资源范围及投递尝试关联一致；不得提前为纯草稿/排队项开放 |
| 确认审批、配置或控制结果 | 绑定有效会话/实例/操作并保留实际确认程度；迟到结果不修改新实例 |
| 包变更生效 | 有效版本、所用私有状态和相关绑定可一致判断；中断不会留下半套新旧状态 |
| 内容回收 | 保留关系、未决责任及活动读取/写入条件已复核，删除不会与新增引用竞态 |

必要操作记录使用稳定身份和有限结果状态，重建 UI 或恢复本地操作时查询既有结果，不重复执行原生操作。宿主命令去重不等于 Agent 端幂等；停止已经确认也不证明之前输入未被消费。可以释放不再有用途的过程表达，不能丢弃仍承担未知结果或授权依据的最小事实。

恢复材料保持足以核对身份、配置、版本和必要任务关系的范围，不把全部正文、子任务快照或诊断日志塞入一个 recovery 字段。正文和任务记录通过稳定关系读取。原生 ID、路径或恢复描述不证明原生内容仍存在；本地恢复记录也不自动启动 Agent、重新授予旧连接访问或补发输入/审批。

包状态转换及宿主数据格式演进都需有可核对的提交/完成结果和原材料保护；失败不清空原库或覆盖唯一历史来“修复”。派生索引可以重建，权威数据损坏不能用清空重建代替恢复。可用部分可以继续只读呈现，无法确认的部分说明限制；本票不因此承诺未选的完整备份/恢复产品或旧 Aibo 数据迁移。

### 引用摘录与内容保留

初始摘录采用最近 3 个可明确识别的主会话回合及其关联工具记录，每条最多 12,000 字符，全部引用摘录合计最多 32,000 字符。可包含已识别的自主回合或未完成回合并标明状态；不能以任意三条消息伪称三轮。默认不展开全部子 Agent 过程，固定成员仍可按已确认权限补读。

字符预算按 Unicode 码点计算，不是 UTF-8 字节、模型 token 或显示宽度。工具正文及必要的角色、来源和省略说明计入最终摘录预算。草稿新增/编辑引用时按确定的顺序分配预算，保证每项可识别并显示实际省略；不能因合计超限悄悄丢掉整条引用。无法容纳必要说明时要求用户调整引用或预算，不能把不完整输入当已通过检查。

摘录可以缩减，但固定引用历史版本本身不因此变成截断后的版本。用户选择附带全文时，超限不能静默改为摘录；实际发送还须满足接收 Agent 的内容和输入限制。工具补读只在真实支持时提供，分页始终对应同一固定版本；字节资源与文本分页分别受有界读取合同约束。

修改默认预算不改写已排队或已发送输入；后续补读也不修改旧引用。已保存历史、草稿、队列、发送记录、有效授权及未决操作共同形成内容保留关系。取消一个关联、归档、移除工作区入口或卸载包，不代表所有关联都已解除。

保留关系与活动读取保护是宿主数据合同的一部分；共享字节或引用计数是实现手段，不可只看某个 UI 是否关闭或索引是否还命中。删除索引不能触发源历史回收，撤销读取授权也不自动删除用户已保存内容。

### 搜索的来源与故障边界

| 搜索对象 | 来源与可见范围 | 定位及更新要求 |
| --- | --- | --- |
| 会话与消息 | 宿主目录/已保存消息；支持跨工作区，默认纳入所选范围内归档及已移除工作区保留历史 | 使用稳定会话/记录身份及原文范围定位，标明来源状态；不依赖 Agent 在线 |
| 工作区文件名、路径和文本 | 用户选择工作区的当前磁盘内容，默认遵循忽略规则并排除隐藏内容 | 可显式扩大过滤范围；跳过/读取失败/资源限制有说明，文件变化后重新核对命中 |
| 应用命令、Agent 命令和 Skills | 应用注册与已取得的 Agent 发现结果 | 标明是否可用、缓存或可能过时，不为搜索调用创建/恢复原生会话 |
| 设置与插件 | 当前设置描述及包管理目录/贡献元信息 | 搜索名称、说明及必要状态；不把凭据、私有恢复内容或全部设置值当搜索正文 |

主会话消息检索不自动扩展到工具全文、独立子 Agent 历史、附件或产物搜索，未选项保持原范围。跨工作区搜索结果不授予 Agent 跨工作区引用或任意读取能力；已归档/来源不可用的历史可搜索，也不扩大从这些来源新建引用的承诺。

搜索索引独立、可重建；源提交记录足够的版本/更新依据，使索引中断后能追赶，不要求历史保存等待全文索引完成。结果落后、重建中或部分不可用时明确说明，不能把索引没有命中当作历史不存在。索引恢复不能覆盖源数据，损坏时可从源重建且不启动 Agent。

工作区文件索引若持久化，必须具有来源及失效/重建依据；它是当前文件的派生表示，不是历史文件备份。移除工作区后不继续把该目录当活动扫描来源；用户保留的会话历史仍可搜索。文件搜索在所选范围和授权内只读运行，不执行项目代码，也不因路径或符号链接自动扩大到工作区外。

### 诊断与内部回收

诊断日志与业务/恢复事实分开保存和清理，初始最多 14 天及 100 MiB，总量包含当前写入中的诊断文件，不为每个模块各给一份独立的 100 MiB。达到任一限制先清理最旧日志；单条记录、待写缓冲和轮转过程也要有界，不能靠一条巨型错误消息绕过预算。

记录受控的事件、时间、关联身份、状态和必要错误说明；错误信息经过筛选、去敏及长度限制，不常态保存正文、工具全文、附件字节、完整环境变量或凭据。通过关联身份定位已保存业务记录，不把长期必要审计事实塞进会按预算淘汰的日志中。临时详细采集和诊断包导出仍未纳入首版。

日志失败不阻断业务保存和执行；在设置中提供实际日志状态及目录入口，避免为记录日志写入失败而递归生成无限日志。诊断预算不包含业务内容、附件、恢复数据、派生索引、数据库内部日志或外部 Agent 自己写入的文件，不能宣称全应用磁盘总量只有 100 MiB。

无主托管资产按以下条件回收：

1. 资产位于宿主管理范围，且能够证明没有历史、草稿、队列、固定引用、恢复、包变更/失败处理或其他未决操作责任；程序卸载、来源失效或文件年龄本身不足以证明无用途。
2. 标记为可回收候选后默认等待 24 小时。缓冲期间新增关联或发现未完成责任，就撤销候选资格；不能按原先一次扫描结果直接删除。
3. 回收时再次核对最新关系和活动读取/写入，保证删除与新增使用互斥；中断后可核对并继续本地收尾。关系不明、检查失败或存在未完成写入时保留并报告内部维护状态。

适用对象包括已解除关系的托管附件/内容、无恢复责任的失败候选包和不再需要的旧程序资产。仍用于重装恢复的私有状态、旧转换原材料、引用版本或未知投递证据受到保护；不能把“包私有”统一当缓存。用户工作区文件、Agent 原生数据不属于这些候选。

不为完成内容和必要事实均已落盘的纯传输缓冲建立永久副本；派生索引及其他明确可重建缓存按其独立失效/预算规则处理。24 小时规则针对无主托管资产，不把全部原始事件都保存一天，也不使它们自动获得业务保留资格。逻辑内容回收与存储文件实际缩小分别判断；不增加未选的数据库压缩或完整数据管理界面。

### 关键数据失败后的运行

历史、队列、投递/恢复证据等关键数据无法可靠保存时，停止新的受影响工作，并按能力请求停止当前执行、暂停目标及结束相关后台任务。停止、拒绝新的授权请求和撤销访问等减少影响的操作，不应因无法保存记录而永远被阻塞；其实际执行及记录结果必须如实标明。

故障期间可以有界暂存收到的内容和控制结果，但不能把内存暂存称为持久成功。正常历史发布仍遵循 Q60；故障提示若展示暂存内容，明确标为未保存，与已提交历史分开，不进入已固定引用或被索引为已保存历史。缓冲耗尽、来不及保存或进程中断时标明缺口，不无限占用内存或声称内容完整。

请求停止不代表原生工作已停，Agent 不支持的控制也不能用虚假终态替代。应用尽量保留必要事实；存储故障使其无法持久化时，必须说明限制，不承诺故障期间仍有完整恢复记录。修复后先核对和保存可恢复状态，再由用户明确恢复执行，不自动补发未知输入或恢复目标。

单独索引损坏/滞后及日志失败按各自机制处理，不自动停止 Agent。若它们挤占资源进而导致关键数据无法保存，则进入上述关键故障路径；先限制可重建/可淘汰数据，不能以删除受保护历史来恢复写入。

### 逻辑接口、验收及后续归属

| 接口职责 | 调用方依赖的合同 |
| --- | --- |
| 提交业务内容及必要事实 | 返回可靠提交结果和稳定版本；未保存不发布为已保存历史，失败有明确影响范围 |
| 保存/转移输入与资源关系 | 草稿、队列、尝试及引用/附件关联一致，调用重试不重复建立业务输入 |
| 读取/固定内容版本 | 有界读取、固定范围及完整性说明，旧引用不依赖最新原生状态 |
| 派生检索与索引恢复 | 来源可追溯、定位稳定、滞后可见；可重建且不修改权威内容 |
| 判断保护与回收候选 | 汇总全部责任并复核，等待 24 小时后仍须检查竞态，不依赖 UI 或单个引用计数 |
| 写入有界诊断 | 字段受控，统一 14 天/100 MiB 预算，失败不作为业务保存失败 |
| 核对中断与数据演进 | 能判定提交状态和所用版本，不以原生执行试探恢复，不清空唯一数据自愈 |

验收至少覆盖：

- 流式内容提交前中断、提交后发布前中断，以及最后一段/终态竞争：显示与保存的范围一致，不把未保存内容标为完成。
- 同一输入/附件/引用的草稿入队、取消、手动重发、包变更及崩溃恢复：身份、保护关系和未知结果不丢失，也不因重放形成重复业务记录。
- 原生重放/补读、重复状态与历史物理合并：原文和固定版本等价，不合并两次不同发生的同文输入，不永久复制每份完整快照。
- 引用预算、多来源合计超限、未完成回合及无全文工具能力：摘录可辨、缺口明确、版本固定，字符预算不被宣称为模型容量。
- 索引丢失、落后、重建和文件变更：历史仍可读，搜索可解释，命中定位可核对，重建不启动 Agent。
- 归档、移除工作区、包卸载：已有历史默认可搜索，来源状态可见，实际文件扫描和 Agent 引用权限不被暗中扩大。
- 无主资产候选期间重新加入草稿/引用、并发读取、包恢复及回收中断：24 小时后仍须复核，不删除受保护内容或用户原生文件。
- 日志超过期限/容量、超长错误、轮转失败及日志目录不可写：预算与错误状态可验证，业务数据不随日志清理丢失。
- 核心存储不可写、损坏及有界缓冲耗尽：暂停推进、独立核实停止、明确缺口；修复不自动续跑或补发。
