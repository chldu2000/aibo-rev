关键事实：

- 旧能力插件是可贡献宿主状态、操作与语义视图的扩展，实际 greeting 示例走 Capability Runtime；它不是 MCP 包的同义词。当前已选“可安装能力插件”，但未选独立工具面板等具体贡献场景，产品范围仍须由用户明确。
- Agent 会话提供者、语义视图、宿主工具/MCP 接线、toolView、工程任务及 ACP 厂商扩展是不同角色，不能混称一种能力，也不要求新架构继承旧 Runtime 或 manifest。
- 旧安装替换会暂存候选、复制宿主管理的私有数据，并恢复真实原生会话验证同一身份及基础能力；这不是无执行的兼容检查，不能直接替代新架构的恢复授权规则。
- 安装替换的失败保护与独立逐会话迁移不同。前者恢复整体宿主绑定/启用状态，后者逐会话返回成功或失败；都不能被推广为任意原生状态可逆。
- 宿主历史、会话绑定、包私有恢复状态及 Agent 外部原生存储分属不同责任。恢复旧绑定不回滚外部原生数据、设置或工具副作用，也不能证明旧包一定还能恢复原生会话。
- 本地安装、依赖/认证检查、自动下载运行时、在线分发、升级前失败保护、升级后撤销分别是不同承诺；未选功能不随旧实现自动进入新范围。
