## Question

持续目标调度与预算、子 Agent 关系及过程历史、后台任务状态/输出/取消分别由谁拥有，通过何种 ACP 能力进入宿主？

确定原生提供与宿主组织的语义区别，避免把周期性发送 prompt 伪称原生目标，或把工具卡标题推断为完整子 Agent。明确暂停、重启与原生不可达时能保留什么、如何核实状态、哪些结果不能推断。

范围依据：F11.1–F11.3、F12.1–F12.6、F22.2–F22.3。

遵循 [Agent 能力承诺](04-agent-capability-contract.md#answer)：允许高级能力存在差异及采用已验证扩展，但平台仍须逐项交付所选功能。本票须确定每个动作的真实实现路径，不以能力可选为由消除交付缺口。

[历史与引用决议](06-history-reference-authority.md#answer)要求可按需读取固定范围内、已保存且能明确关联到来源的子任务记录。本票须明确这些关系与输出完整性的依据；接收侧子 Agent 的委托读取条件也需明确，不能因存在父子关系就默认扩大到其他会话或最新内容。

[会话控制决议](07-session-control-and-delivery.md#answer)已区分 prompt 结算、下一输入的接收条件与全部活动停止。本票须明确目标/任务如何影响这些状态以及如何独立暂停/停止；恢复若可能自主推进，必须承接用户明确恢复的条件。普通队列暂停是否影响目标自主推进由本票明确，不能混为同一状态；宿主发起的投递都须经过会话控制，遵循其适用的授权、暂停与未知结果规则。

## Answer

2026-11-04，根据 Q46–Q52，采用**Agent 原生推进持续目标，宿主统一协调控制并保存可观察活动**的分工。宿主不实现一套反复发送普通输入的目标循环；目标、当前回合、消息队列和独立后台任务分别表示，不用一个“运行中/已停止”状态代替它们。

### 已确认的用户行为

| 决策 | 已确认行为 |
| --- | --- |
| 目标执行责任（Q46） | Agent 决定原生目标的后续执行和完成状态；宿主经 ACP 创建、查看及控制，缺失动作逐项说明 |
| 暂停消息队列（Q47） | 只暂停待发送用户消息；不暂停目标或取消已运行任务 |
| 取消当前执行（Q48） | 沿用暂停未发送队列，并同时请求暂停目标；按实际能力和证据确认效果，不将清除当作暂停 |
| 独立后台任务（Q49） | 提供任务独立取消；不随当前回合额外批量停止所有子任务，原生取消的实际影响照实记录 |
| 接收侧子 Agent 补读（Q50） | 可使用父会话已授权的固定版本与资源范围；不能扩展到其他会话或最新内容，无法细分身份时按父会话记录访问 |
| 额外内容补读（Q51） | 打开详情或用户明确要求时补读并保存；ACP 已推送的内容持续保存，不以 UI 是否展开为条件 |
| 独立目标控制（Q52） | 单独暂停/清除目标只执行相应原生目标动作，不额外取消当前回合或暂停消息队列；不承诺原生动作完全不影响当前执行 |

### 运行与控制的责任

Agent 拥有目标执行策略、原生重试和完成判断，以及由其创建的子 Agent 与后台任务的原生生命周期。宿主不从一句“完成了”、工具标题或前台 prompt 结束推断目标完成、父子关系或全部任务停止，也不另建通用子 Agent 调度器。Agent 请求宿主实际执行的文件、终端等操作，仍遵循[会话控制、授权与消息投递的责任](07-session-control-and-delivery.md#answer)中的宿主执行与授权责任。

目标控制经过同一会话控制入口，验证会话身份、信任、连接代际、动作能力及当前条件。它不是普通排队输入；原生适配器内部将目标动作编码为命令或输入，也不能让宿主绕过控制记录，或把目标动作当成可盲目重发的只读设置。

创建/恢复目标可能立即推进工作，属于明确的执行意图。单独恢复目标不自动恢复已暂停消息队列；恢复队列也不隐式请求恢复目标。普通输入继续按既定队列规则及实际可接收条件投递，不因存在等待输入就由宿主自动暂停、抢占或恢复原生目标。用户可以按实际能力选择插话、暂停目标或取消当前执行。

取消当前执行是一项组合意图：保留并暂停普通队列，请求取消当前执行，并在支持时请求暂停目标。各动作分别保留结果；暂停未确认不能显示目标已停，目标暂停也不能作为当前回合结束的证据。缺少暂停能力时明确说明目标仍可能继续，不用 clear/set 模拟暂停/恢复。不能因一个控制请求等待响应而阻塞其他停止操作。

暂停或清除目标仅控制该目标。暂停不清除目标内容；清除不删除已有历史及引用。宿主不额外取消当前回合、暂停队列或批量停止后台任务，但必须呈现原生动作本身产生的影响。目标、回合、队列和任务之间的联动方向由上表确定，不能因按钮名称相似而推导对称行为。

目标控制、任务取消都区分用户请求、Agent 报告的状态及其确认程度。超时、断连和乐观状态更新不能证明动作已生效；结果未知时保留操作关联与待核实状态，不自动重发 set/resume/clear 或取消后重新创建目标。旧连接的迟到结果不能修改新目标或新任务。

Agent 自行处理的工具错误或原生目标重试，不自动升级为整个目标失败；目标是否完成、暂停、失败或等待条件依据明确语义映射。宿主不能自行启动新目标来“修复”终止失败。普通输入/回合失败对队列的影响继续遵循既定会话控制规则。

### 能力映射与可实施路径

标准 ACP 与厂商扩展由共同接入模块及独立扩展处理模块转换；核心和 GUI 使用相同的活动、控制结果及能力语义。以下为逻辑责任，不要求增加进程、单独后台服务或另一套宿主目标协议。

| 能力 | Agent／适配器提供 | 宿主承担 |
| --- | --- | --- |
| 目标创建、状态、清除 | 原生目标控制及状态证据，经协商后的 ACP 扩展公开 | 控制意图、状态呈现和必要历史；不从界面文本推测完成 |
| 目标暂停/恢复 | 独立动作及其真实效果，不能以清除/重建替代 | 按能力启用，处理与回合/队列的明确联动及未确认状态 |
| 目标预算/用量 | 实际报告的数值、单位、统计范围与原生限制信息 | 显示来源与缺失；不把会话总用量冒充目标用量，不把缺失值填成零 |
| 子 Agent 列表及历史 | 明确身份、父子关系、状态及可获得的消息/工具记录 | 持久关联、离线阅读及已保存内容的固定引用 |
| 后台任务列表及输出 | 任务身份、状态、输出内容或可用的读取合同 | 保存收到的正文，按需读取额外内容，表达缺口和不可达 |
| 定向取消 | 针对实际任务的控制能力及范围，必要时包含后代影响 | 目标身份校验、控制记录和停止核实；不把请求成功当全部任务已停 |

依据 [ACP 目标控制与子任务补读的实际边界](15-acp-goal-task-evidence.md#answer)及既有能力研究，架构采用以下有证据的路径和限制：

- 固定 Codex 适配器提供目标 set/pause/resume/clear，并映射原生目标操作；对应依赖版本中，暂停/清除可阻止目标后续续跑，不能据此声称当前回合或后台任务结束。创建/恢复 active 目标可能启动新回合。
- 固定 Claude 适配器仅提供目标 set/clear，内部可能通过插话或新回合执行命令，并发布乐观状态。不能将这些动作等同于静默修改设置，也不能用 clear/set 宣称完成 F11.3 的暂停/恢复。
- 两家都有子历史与后台状态/取消的代码路径，但关联、输出及控制范围不同，须按所协商版本转换。原生会话 load/resume 及某些历史恢复路径可能启动执行，不能默认成为只读补读接口。
- 已有结构化消息、子历史重放和任务输出流可作为宿主保存与离线阅读的来源。额外的只读子历史/任务输出补读，在所查样本中尚无完整共同合同；需要针对可用路径验证，必要时采用有限的 ACP 扩展，不能让 GUI 直接解析各 Agent 的原生库或另接原生执行协议。
- F11.2 是预算/用量展示，不在本票增加通用预算设置或宿主强制限额。类型中存在可选字段不代表运行时一定报告，正式交付仍需实际数据证据。

不同 Agent 可以缺少某项动作，但平台仍须为每项所选功能提供真实可验收路径；缺失按钮、空值和说明不是已交付功能。已有固定源码路径也不是已验证组合，具体版本、扩展维护与运行验收继续由包生命周期及最终验收票承接。

### 子任务历史、补读与引用

子 Agent 和后台任务记录以原生明确标识及可核实关系归属到 Aibo 会话，保留来源与实例范围。相同标题不能合并不同任务，旧任务 ID 的迟到事件不能挂到新实例。一个子 Agent 也可能在后台运行；列表分类不能将同一原生活动重复认定为两份独立工作。

事件接收与持久保存独立于当前视图和前台 prompt。即使用户切换会话、未展开子任务，或目标正在自主执行，已收到的消息及工具输出仍纳入可观察历史；UI 不承担 ACP 事件接收及持久保存责任。必要历史与控制证据不等于永久保存所有进度心跳、重复状态快照及协议原包，具体合并和保留规则由持久数据票确定。

需要额外调用才能取得的内容按 Q51 补读。读取先使用宿主已保存内容；补读前核对能力、来源、授权和读取是否可能推进执行。提供补读能力的 ACP 适配器负责封装原生只读 reader 或受限的任务输出资源；合同须明确任务身份、所读范围/游标和完整性，不能接受任意文件路径作为读取授权。没有可靠只读路径时说明不可补读或缺失，不因展开详情、搜索或准备引用就静默启动 Agent。用户明确恢复原生执行后随恢复自动推送的历史仍应保存，这不属于宿主主动全量补读策略。

输出记录必须区分已保存正文、摘要、路径提示、截断或缺失部分及来源不可达。输出文件路径不是已保存附件，也不自动授予读取该路径的权限；不能用磁盘当前内容补造过去某时刻的任务输出。任务结束不证明历史完整，读取失败也不删除已保存部分。

后续补读可扩充宿主最新可观察历史，但不能重写既有完成内容、扩充旧引用成员或替换固定附件。跨会话引用只包含冻结时已保存且能明确关联的子任务与输出；之后发现的子 Agent、补回的消息或新输出须经显式刷新形成新版本才进入引用。

接收侧子 Agent 的补读沿用父会话授权范围，由宿主控制的连接/凭据绑定，不接受模型自报父子 ID 作为授权。无法可靠识别具体子 Agent 时，审计事实只归属父会话；不承诺不存在的子 Agent 隔离。父子关系不扩大到来源最新记录、其他会话或其他引用的全文。工作区信任撤销后，同一父会话范围内的委托读取也立即受阻，已保存内容仍保留。

### 恢复、停止与逻辑接口

重启、归档及来源包不可用后，继续阅读已保存的子历史、任务输出和目标记录，不依赖原生执行恢复。恢复本地记录时保留最后已知状态及待核实事实，不将旧“运行中”当成当前实时状态，也不自动标为完成或失败。

原生恢复若可能唤起目标、子 Agent 或后台活动，必须纳入用户明确恢复的操作范围；不能为了核对状态而偷偷执行。目标控制内部若先恢复原生会话，也须约束该适配器行为或明确纳入恢复授权，不能为暂停/清除目标静默唤起它。若不能独立恢复所选部分，就说明能力限制，不承诺只恢复队列却暗中推进目标。断连后的适配器自动恢复同样受既定恢复合同约束。

活动列表及控制证据共同供会话控制判断接收新输入、归档、移除及退出条件；其中“当前 prompt 已结算”“目标已暂停”“某任务已结束”互不替代。按任务能力取消并核实实际范围；清除目标或取消一个子 Agent 不代表其全部后代和独立后台任务均已停止。未确认状态继续遵循等待/明确强退等既定生命周期规则。

对外接口围绕少量完整职责组织，具体方法名及存储形态留给后续架构票：

| 接口职责 | 调用方获得的合同 |
| --- | --- |
| 查询/订阅目标及活动 | 返回共同状态、关系、动作能力与证据有效性；视图替换不改变运行或持久责任 |
| 请求目标变更或任务取消 | 表达明确目标和操作身份，返回进行中、已确认、不可用或待核实；不隐含全队列或全部任务控制 |
| 阅读已保存历史、按需补读 | 返回内容范围及缺口；只读能力不足时不得转成执行恢复，新增内容不修改旧引用 |
| 核对及明确恢复 | 区分本地重建和原生执行动作，保留未知结果与已确认的恢复范围 |

共享无界面交互模块使用这些合同组织操作与错误状态，呈现包负责表达当前影响及禁用原因。业务规则和厂商差异不能散落到每套 GUI。

### 验收与后续归属

| 场景 | 必须证明的结果 |
| --- | --- |
| 目标自主执行且无前台 prompt，用户切换/重载 UI | 活动状态和收到的消息持续保存，视图不拥有执行 |
| 暂停队列、取消当前执行、独立目标控制 | 按 Q47/Q48/Q52 区分影响，暂停和取消分别确认；不擅自恢复其他部分 |
| 目标已暂停但当前回合/后台任务仍运行 | 不显示全部停止，不据此跳过归档/退出的活动核实 |
| 缺少目标暂停能力或目标动作结果未知 | 不用 clear/set 模拟，不自动重发，保留禁用原因或待核实状态 |
| 原生目标动作通过命令/插话实现 | 呈现实际执行影响及确认阶段，不把乐观快照当停妥证据 |
| 任务定向取消、原生级联及旧实例迟到 | 作用于正确活动，按合同反映后代影响，不串用新任务身份 |
| 未展开子任务、离线、重启或来源包不可用 | 已收到并保存的历史仍可阅读；不需要启动 Agent |
| 按需补读没有可靠只读路径 | 展示已保存内容与缺口，不通过 load/resume 隐式执行 |
| 后续补读、输出截断或新发现子任务 | 新内容有来源及完整性标记，旧引用版本和资源范围不变 |
| 子 Agent 补读引用及撤销信任 | 使用父会话原授权范围，拒绝越界；不能识别子身份时不伪造审计归属 |
| 预算/用量字段缺失或单位/范围不同 | 不填零、不混用会话与目标统计，不宣称宿主实施原生限额 |
| 创建/恢复目标与普通输入竞争 | 遵循实际接收条件和已确认控制意图，不自行抢占目标或重复投递 |

- [Agent 包、能力包与呈现包的生命周期](09-package-lifecycle.md)：交付并约束高级 ACP 扩展版本；包替换须保留目标/任务身份、未决控制及历史，不重建目标或重发未知操作。
- [持久数据、搜索与诊断的所有权](10-data-ownership-and-search.md)：确定活动状态、控制证据、关联历史、输出缺口及补读去重的保存/回收；固定引用保护已关联内容，不以可重建进度代替业务历史。
- [模块接口、技术栈与桌面部署形态](11-module-and-desktop-architecture.md)：将上述逻辑职责落实到模块，不因此新增宿主调度循环或要求每类活动一个进程。
- [架构验收与旧版切换的承诺](12-architecture-acceptance-and-transition.md)：按真实 Agent/适配器/原生版本验证目标、子任务、后台输出与恢复路径；补读及控制缺口须补齐或明确限制，不能以静态研究替代完整功能验收。
