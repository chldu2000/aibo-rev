关键结论：

- 固定 Codex 适配器的 goal set/pause/resume/clear 映射原生目标操作。对应锁文件中的原生 0.165.0 源码显示：暂停/清除阻止后续目标续跑，但不因此中断已经启动的回合或停止后台任务；set/resume 可能启动新回合。该依赖样本不证明用户实际运行的二进制版本。
- 固定 Claude 只有 set/clear，经插话或新 prompt 发送命令；可能影响当前执行，快照也可能是乐观更新。返回成功或 null 不能直接证明原生已清除，更不能证明全部工作停止。
- 目标动作可能在执行前先恢复原生会话；不能为了暂停/清除或核对状态而忽略恢复副作用。控制结果和实际活动需分别记录。
- 两家都可在不展开 UI 的情况下推送子消息/工具和后台更新。父 load 还会主动回放子历史；已收到内容可由宿主持久保存。
- 内部只读 reader 的存在不等于公开了独立 ACP 补读接口。现有父 load 可能启动或恢复执行，不能透明替代打开详情时的只读补读；后台输出全文及断线缺口也没有已核实的共同补读合同。
- 原生身份和结构化关联是子任务归属的依据，标题、路径提示及空回放不能证明身份、全文完整性或读取授权；定向停止只按对应任务的合同取证。
