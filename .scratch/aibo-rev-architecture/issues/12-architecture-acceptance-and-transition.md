## Question

这套架构用哪些端到端场景证明可实施、框架可替换、运行可恢复且历史可引用？哪些证据缺失需要额外研究或原型票？

核对全部 83 项选择都有明确责任、接口和验收入口；以真实 Agent 跑通关键链路，两种框架验证完整关键交互与故障回退，并覆盖 macOS/Windows。此票定义验收，不执行产品实现。

明确旧 Aibo 历史/附件/配置及原生恢复状态的迁移承诺是否进入交付范围，或另开地图；D08 尚未选中，不能替用户承诺或放弃。区别前序新包升级迁移与旧应用数据迁移。

地图终点为可实施架构规格；实施任务拆解、正式库迁移和发布在本图之外。

功能覆盖遵循 [Agent 能力承诺](04-agent-capability-contract.md#answer)：所有 Agent 验证基础门槛，所选平台功能逐项有真实路径；不要求所有 Agent 高级能力对等。验收须区分已验证组合与允许接入的未验证组合，并记录所采用扩展的合同与维护责任。

呈现覆盖遵循 [呈现接口决议](05-presentation-interface.md#answer)：可启用的完整呈现包须覆盖所有必需的用户操作和信息展示。区分原型中的关键流程样本与最终完整覆盖，不以包声明或单个跨框架控件证明工作台可替换。

引用验收遵循 [历史与引用决议](06-history-reference-authority.md#answer)：验证摘录与分页全文的固定版本一致性、关联任务/附件范围、缺口表达、调用者授权、来源失效后的可读性，以及共享内容与未决投递的保留；不能仅凭一次成功读取主会话文本宣称完成全部引用能力。

控制验收遵循 [会话控制决议](07-session-control-and-delivery.md#answer)，覆盖投递响应丢失、取消/插话竞争、配置与旧审批、信任撤销和原生恢复副作用。[控制证据研究](14-acp-control-evidence.md#answer)中的固定实现缺口须有明确降级或补证；原型的模拟内核不能证明真实 Agent 的消费、停妥或凭证隔离。

目标与子任务验收遵循 [持续目标、子 Agent 与后台任务的职责](08-goals-and-background-work.md#answer)，验证取消当前执行与独立目标控制的不同联动、目标暂停后仍存续的活动、无前台 prompt 时的历史保存、按需补读的无执行性质及父会话引用授权。依 [目标控制与补读研究](15-acp-goal-task-evidence.md#answer)固定实际原生二进制与握手组合，核对乐观快照、恢复副作用、缺失输出及定向停止，不将类型字段或静态调用路径当作已交付证据。

包验收遵循 [Agent 包、能力包与呈现包的生命周期](09-package-lifecycle.md#answer)：真实安装并使用 Agent、工具/上下文能力及完整呈现，验证活动期间变更、必要迁移失败、中断恢复、旧实例迟到、卸载后离线可读与重装后明确恢复。检查不得启动原生工作，宿主迁移成功与原生恢复实测分别记录；工具和用户选择上下文两条路径都要验收，不能用空包或模拟恢复充当 F19 的交付。

数据验收遵循 [持久数据、搜索与诊断的所有权](10-data-ownership-and-search.md#answer)：在真实存储及 macOS/Windows 上安排提交/发布间中断、关键写入失败、索引损坏/滞后、日志轮转及资产回收竞争等场景。核对固定引用与原文完整性、草稿/队列/恢复材料的保护、诊断双限额和延迟复核，区分逻辑回收与磁盘文件缩小。模拟未保存状态不能证明实际持久性；内部一致性和无主资产回收不等于已经承诺全部 F23、旧库清理或迁移。

用户 Q71 允许先按单平台证据继续候选讨论，但[桌面候选在 Windows 的关键验证](17-windows-presentation-validation.md)必须在本票收口前完成，不能将另一平台的关键验证无限推迟至实施后。正式版本暂不限定设计系统或呈现风格；验收关注既定功能、交互、替换与恢复合同。

## Comments

2026-11-04，用户接受呈现原型基本通过并要求提交主架构文档，正式技术栈、UI 与交互留待后续单独设计。本次提交是阶段架构基线，不是本票的最终产品验收或旧版切换承诺；本票保持 open/unassigned。原型接受结论见[跨框架替换与呈现故障回退的最小原型](13-presentation-conformance-prototype.md#answer)，后续验证根据正式方案继续安排。

2026-11-11：用户决定旧版 Aibo 的数据（历史、附件、配置及原生会话的可恢复状态）不迁移，D08.2–D08.4 不进入交付范围、不另开地图。本票不再需要定义旧应用数据迁移的验收；新包升级时的私有状态迁移仍按 09 号决议验收。旧版切换只剩“新版从空数据开始”的说明与用户提示，是否需要在首次启动时提示旧数据位置，留待验收定义时确认。

2026-11-11：用户决定默认界面改用 MyGO 原生 UI，并取消外部完整呈现包（[ADR 0006](../../../docs/adr/0006-native-ui.md)，Q112–Q114）。本票的验收随之修订：

- 不再验收“两种框架替换完整关键交互”、外部呈现包的完整性与兼容检查、换包后的状态恢复与明确失败自动回退（F20.4–F20.7 已取消勾选，必需项为 81 项）。
- 界面验收改为 `go -C tools/ui-checks run . all`：令牌与源码规则、要求文档映射，以及用 MyGO `ui.Tester` 运行的验收用例（[界面硬性要求](../../../docs/design/ui-requirements.md) §11）。当前只有原型目标与 5 条用例；产品实现成为验收目标后补齐其余用例并开启 `requireAllUITests`。
- 仍须验收：原生界面在重建或重启后恢复共通状态；能力包工具面板的安装、打开、收起、重载、故障与卸载（F17.1）。
