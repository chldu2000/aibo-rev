## Question

切换/重载/替换呈现、UI 崩溃、关闭最后一个窗口和明确退出应用时，会话、排队消息、持续目标与后台任务分别应继续、暂停还是终止？

用这些场景确定必要的进程存活与状态归属，再讨论是否需要常驻运行时。重启后可恢复不等于退出后仍执行；本票不预设 daemon 或桌面容器。

同时区分工作区移除、会话关闭和会话归档对目录身份、正在运行的任务及历史可见性的影响，避免把移除入口隐式实现为删除历史。

范围依据：F03.3–F03.4、F04.6–F04.8、F09、F11–F12、F20.7、F21.4–F21.5、F22.2–F22.3。

## Comments

2026-11-01：根据用户“接下来我需要做什么”，开始本票并认领。先讨论用户可观察的存活行为，再推导进程划分；尚未选择桌面容器或常驻服务。

首轮待用户回答（推荐不视为已接受）：

- Q5：呈现切换、重载或单独 UI 故障时，执行是否继续？推荐继续，由恢复后的视图重新连接会话状态。
- Q6：关闭最后窗口与明确退出应用分别意味着什么？推荐关窗后应用留在后台，明确退出时确认并结束可控执行、保存恢复信息；不在退出后继续自动发起工作。
- Q7：关闭会话与归档会话如何影响活动？推荐关闭只是收起视图；归档前明确处理活动与未发送队列，不让归档静默隐藏运行任务。
- Q8：移除工作区是否影响历史及活动？推荐保留历史与磁盘项目文件，移除前明确处理该工作区活动和未发送队列。

运行过程强制退出或崩溃后，外部任务是否真实停止必须按证据核对；本轮行为偏好不等于已经证明所有 Agent 都可可靠终止或恢复。

## Answer

2026-11-01，根据用户 Q5–Q11 的选择，采用**随应用存活的运行核心与可重建会话视图**这一生命周期要求。它确定存活与恢复责任，具体语言、桌面容器和进程部署仍由后续票选择。

| 场景 | 已确认行为 |
| --- | --- |
| 在会话间切换、重载或替换呈现包 | 会话运行、队列、持续目标与后台任务不因视图离开而停止；新视图重新连接现有状态 |
| 单独 UI 故障 | 执行继续；恢复视图或回退默认呈现。此要求不代表整个运行核心崩溃后还能连续执行 |
| 关闭最后一个窗口 | 应用留在后台，继续按当前授权与队列状态运行；应能重新打开工作台 |
| 明确退出应用 | 有活动时先确认，停止继续投递/推进工作，结束可控执行并保存恢复信息；不要求应用退出后继续工作的常驻服务 |
| 停止请求迟迟未获确认 | 展示未确认的活动，允许继续等待或主动强制退出；保留状态待核实记录，不把强退等同于任务已停止 |
| 应用重新启动 | 恢复历史、草稿、队列与目标状态，核对原生情况，由用户明确恢复执行；不自动继续工作或补发结果未知的输入 |
| 归档会话 | 有活动时提示先停止或等待完成，确认无活动后才能归档；未发送队列保留并暂停 |
| 移除工作区 | 有活动时同样先停止或等待完成，确认无活动后移除；保留业务历史、项目文件和暂停的未发送队列 |

**会话关闭入口是条件项。** 日常交互以会话间切换为准，本票不要求独立的“关闭会话”操作，也不选定标签页。只有采用标签页等形式时，才进一步决定是否提供关闭入口及其具体语义；Checklist F03.3 已按用户修正增加条件说明。

**对后续架构的约束：**

- ACP 连接、执行调度和权威运行状态不能归某个视图或 UI 框架实例所有；呈现故障域必须允许运行核心继续存活。
- 无窗口运行与应用退出属于不同生命周期。后台入口及视图重建方式由呈现/桌面票确定，不在本票预设托盘或特定 OS 的菜单形式。
- 应用重启后的“恢复状态”与“恢复执行”必须分开。若某个原生重新连接/加载动作会触发自主执行，不能将其当作无副作用的自动状态同步；具体协商与核对规则由会话控制票确定。
- 仍未确认的执行不能仅因视图消失、进程断开或停止请求已发送就视为结束。没有前台 prompt 也不代表没有目标或后台任务活动。
- UI 重建时共享状态的取回、订阅失效及迟到回复处理，须通过呈现接口和会话控制接口保证，不能依赖原组件实例存活。
