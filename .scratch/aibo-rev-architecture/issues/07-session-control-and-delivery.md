## Question

一个会话从发送、执行、审批/追问到取消和恢复，哪些状态与顺序由宿主保证，哪些由 Agent 保证？

确定队列、插话、请求身份与代际、模式变更、配置确认、附件绑定、重试和结果未知的处理方式。区分能力支持、当前可用性与操作授权；明确宿主执行文件/终端能力与 Agent 自执行的责任，而不照搬旧版执行配置合同。

特别检查崩溃前后何种证据能证明输入已投递，何时允许重试，以及多视图如何避免重复审批。输出可验证的不变量与小接口，不选择具体数据库。

范围依据：F01.2、F04.1、F04.7–F04.8、F05–F06、F08–F09、F22.1–F22.3。

最低接入门槛与能力差异策略见 [Agent 能力承诺](04-agent-capability-contract.md#answer)。本票细化能力变化或失效时的执行检查、拒绝结果及状态更新；未验证、未支持、暂不可用和未授权须分别处理。

### 控制与投递的责任

每个 Aibo 会话的控制状态有单一逻辑写入入口，避免视图、队列和扩展各自推进同一输入。这是模块职责，不要求每会话一个进程或线程，也不意味着把一个长时间等待的 prompt 放在锁内阻塞取消、审批或状态接收。

宿主负责保存输入正文、附件/路径关系、固定引用版本、队列顺序与暂停状态，准备投递并保存必要证据后才调用 Agent。不能把全部待发送项提前交给原生队列，再把宿主的删除或暂停显示为已经控制了那些输入。Agent 内部队列的存在不转移宿主的交付责任。

区分三种身份：用户输入、向 Agent 发起的一次投递尝试、当前连接/运行实例。重挂载 UI 后查询已有操作结果，不重复提交同一控制命令；宿主范围内的命令去重不等于 Agent 支持请求重发幂等。手动重发创建新的投递尝试，保留关联和可能重复的事实。

状态至少区分以下证据，不能压成一个“发送成功”布尔值：

| 所见事实 | 控制意义 |
| --- | --- |
| 仍在队列、尚未尝试交给 Agent | 可按宿主队列规则删除、暂停或选中立即发送；不是已消费输入 |
| 已开始投递，尚无可靠结果 | 保留尝试及其资源关系；超时/断连不能退回“肯定未发送” |
| 经验证的明确未消费结果 | 在控制状态允许时可采取 Q41 的一次普通投递；不能仅凭错误名称判断 |
| 已有接受/插入/消费的某阶段证据 | 记录具体阶段与来源，避免重发；接受不等于回合完成或业务成功 |
| prompt 已结算 | 记录结束原因及所协商的失败信息；不是所有后台/原生活动已停止的证明 |
| 投递结果或停止范围未知 | 暂停相关推进并保留待核实记录；用户处置不改写原事实 |

队列普通投递按顺序推进，受暂停、信任、有效设置与原生可接收条件约束。立即发送只对选中项建立一次明确意图；插话是独立的投递尝试，不能让同一输入同时处在普通投递和插话两条消费路径。已开始投递的项不能靠“删除队列项”假装撤回。

较新的取消、撤销信任等控制意图会阻止旧尝试的迟到回退越过当前限制。用户明确选择的停止后发送是单项意图，其自身请求停止不恢复普通队列；取得匹配操作范围的停止/可接收证据，且信任、能力与该意图仍有效时，才能发送选中项。证据不足时保持未决，不能仅看到某个 `cancelled` 就自动发送。后台任务的独立控制继续由后续职责票确定。

### 配置、审批与授权

配置请求值、最后确认的会话配置、当前回合的已知实际参数分别表示。投递使用其时序之前已确认的配置；必要设置尚未确认或失败时不能悄悄按旧值发送。按 Agent 返回的实际值和可用选项更新，不承诺改变会话配置会追溯修改正在进行的原生回合。

审批和追问由运行核心保存有效请求，呈现模块只负责显示、填写与提交。回复须匹配会话、连接代际、请求身份及本次有效选项；同一请求只接受一次有效用户选择并形成答复意图。取消、失效、连接更替及迟到回复要按各自合同处理，不能把历史审批记录恢复为可操作按钮。

UI 重载时，仍属于存活连接的请求可以继续呈现；应用或 ACP 连接重建时，先核对请求有效性，不自动重放旧批准。审批答复的传输结果未知也保留歧义。取消单个追问、拒绝一次工具与取消整回合分别处理；具体协议版本要求的取消响应由接入模块负责。

Agent 提供的允许一次、始终允许等选项按本次合同回传；长期决定的范围、记忆与效果由 Agent/适配器负责，宿主不从相同标签推导跨 Agent 自动批准。宿主操作确认偏好不能隐式替代 Agent 发出的有效审批请求。

工作区信任与具体操作授权分开。宿主检查自己实际执行的文件、终端和引用读取等能力；Agent 自己执行的操作仍由其原生执行与权限机制负责，ACP 接入和审批界面不能成为通用沙箱保证。

撤销信任被核心受理后，阻止新的业务投递与宿主业务能力访问，包括已有引用授权的后续 Agent 访问；暂停队列并请求停止已知活动。停止、拒绝待决请求、释放资源、接收结果与记录停止证据仍可进行。已经发起的操作不能被追溯视为未发生；Agent 自行执行的停止结果单独显示。重新授予信任不自动恢复原先暂停的队列。

### 附件、引用读取与恢复

直接工作区文件/目录保存路径与来源关系，不能标为内容快照；丢失路径或无法读取时说明实际失败，不悄悄替换为另一文件。图片与已托管附件在排队及重试期间保留固定内容。实际获得并保存的文件内容才可成为后续固定历史的一部分，不用当前文件补造旧引用的附件。

引用历史版本、读取授权与投递尝试分别记录。草稿或纯排队阶段只保留内容关系，不向 Agent 开放新增版本；开始实际投递时，按目标会话启用该尝试需要的有限读取授权，使收到输入的 Agent 能立即按需读取。明确证明未投递/未消费且无其他有效关联时，可撤回该尝试新增的授权；结果未知按 Q44 保留原范围并标记待核实。

读取权限必须由宿主控制的连接身份/凭据绑定接收会话、固定版本与允许资源，不能相信模型自行填写的 sessionId，也不能扩大为整个工作区。取消一条尚未发送的队列项，不应撤销其他已发送输入仍在使用的同版本授权。撤销信任优先阻止访问，但不删除受保护内容。

应用重启先恢复宿主自己的历史、草稿、队列、设置与授权记录。恢复记录不是启动 Agent、恢复原生 session 或重新开放未核实外部连接的许可；这些动作随用户明确恢复执行，再核对目标身份、信任、能力和原生状态。不会自动补发输入、审批答复或配置写入来猜测旧操作结果。

可能引起自主活动的 load/resume 或适配器内部重连，必须纳入恢复操作的授权与验证范围。无法证明无副作用时，不能为了展示历史或探测状态就自动调用；读取宿主已保存历史不依赖启动 Agent。

### 逻辑接口与证据边界

会话控制模块承担以下接口职责，具体方法名、序列化和存储由后续架构票选择：

| 接口职责 | 调用方需要知道的合同 |
| --- | --- |
| 接受输入与控制队列 | 返回稳定输入/操作身份及排队状态，支持暂停、恢复、删除未发送项和选中项立即发送；不把本地受理称为 Agent 接受 |
| 请求执行控制 | 插话、取消、停止后发送和显式重发各自表达意图；依据能力与当前状态返回进行中、完成、拒绝或待核实 |
| 修改设置与答复交互 | 具有明确目标和有效性条件，保留确认状态；旧请求、无效选项和失效实例不能修改新状态 |
| 接收 ACP 证据 | 标准/扩展模块归一化其能够证明的阶段、失败与来源；迟到事件归属原尝试或待核实记录，不能套到新会话活动 |
| 读取与订阅控制状态 | 向共享交互模块提供快照与更新；UI 重建重新订阅，执行和待决责任不随视图销毁 |
| 核对与明确恢复 | 区分纯本地状态恢复与可能推进工作的原生动作；保留未决事实，由用户明确恢复执行 |

依据 [ACP 控制研究](../../../docs/research/acp-session-control.md)，当前证据要求保留以下限制：

- JSON-RPC ID 不提供 Agent 端重试幂等保证。v1 prompt 最终响应、v2 草案接受确认和模型消费是不同阶段；一般 error、断连和空历史不能作为未消费证明。
- 终止失败可能出现在协商后的扩展元数据中；`end_turn` 或普通响应成功不能替代业务结果判断。
- 固定 Codex 样本的 `promptRequired` 有错误后回退歧义。默认不能把该歧义结果无条件归为未消费；若要启用自动普通投递，需明确协议保证或有限适配修正，并通过对应失败场景验证。Q41 的条件不会因方法返回了某个字符串而放宽。
- 固定 Claude 样本可能强制结算 `cancelled`，而底层 query 仍未确认结束。当前请求结算、可接收下一输入、全部原生活动停止必须分别呈现和判断。
- 原生恢复可启动或复用执行环境，Codex 还有恢复后目标自主推进的证据；不能把恢复操作视为纯历史查询。

### 验收与后续归属

验收需同时覆盖正常行为和失败竞争：

| 场景 | 必须证明的结果 |
| --- | --- |
| UI 重载、宿主回复丢失或重复控制命令 | 不重复创建/投递同一输入，仍能查询原操作；宿主去重不被夸大为原生幂等 |
| 普通发送、选中项立即发送与取消竞争 | 无隐式停止，无重复消费，取消后队列暂停，单项发送不恢复整队 |
| 插话结果丢失、回合恰好结束 | 未消费证据不足时进入待核实；不因 `failed` 或有歧义的 `promptRequired` 自动重发 |
| 设置变更、审批答复与旧实例迟到 | 投递使用正确的确认配置，请求范围与选项不串用；旧答复不授权新的工具请求 |
| 仅 prompt 结算或取消兜底返回 | 不将后台/原生活动全部标为停止；保留活动与停止证据的独立状态 |
| 文件变化、托管附件、排队引用 | 路径与快照语义可辨，固定内容不变化；草稿/纯队列项无提前读取权限 |
| 已投递结果未知，再撤销工作区信任 | 保留未知记录及内容，立即阻止后续宿主业务访问；不伪称外部活动已停 |
| 应用重启或原生恢复具有副作用 | 历史仍可阅读，不自动启动目标或重放未知输入；明确恢复后才按合同接续 |

- [持续目标、子 Agent 与后台任务的职责](08-goals-and-background-work.md)：任务独立停止、接收条件、预算/目标推进及接收侧子 Agent 的委托读取；不得绕过会话控制自行补发。
- [Agent 包、能力包与呈现包的生命周期](09-package-lifecycle.md)：升级/卸载时处理控制代际、有效审批与连接授权，保留未决责任。
- [持久数据、搜索与诊断的所有权](10-data-ownership-and-search.md)：输入、投递尝试、确认配置、授权与恢复证据的持久边界及回收；不默认永久保存全部协议原包。
- [模块接口、技术栈与桌面部署形态](11-module-and-desktop-architecture.md)：实现控制模块、传输和状态发布的职责划分，选择进程与调用方式。
- [跨框架替换与呈现故障回退的最小原型](13-presentation-conformance-prototype.md)：通过模拟控制状态验证跨框架交互及失效实例处理，不能据此证明真实 Agent 的停止或幂等。
- [架构验收与旧版切换的承诺](12-architecture-acceptance-and-transition.md)：按实际协议版本与 Agent 组合验证本票场景，保留研究缺口及不支持能力的降级条件。

本票形成接口与行为决议，未实现会话控制逻辑或运行真实 Agent；研究的固定源码证据不等于已验证组合。
