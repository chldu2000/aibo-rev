## Question

ADR 0006 与界面方案 §15 中尚未验证、但不依赖 Windows 的项目，在 macOS 上能否成立？是否需要修正界面方案或 ADR？

1. 原生工作台与工具面板 WebView 合并到同一窗口：可拖动分隔条调整宽度、窗口缩放、收起/展开后页面保留（F17.5）、键盘焦点在原生 UI 与面板之间往返、面板卡死或渲染进程被结束时工作台仍可操作并能重新载入（ADR 0006「尚未验证」第 2 项）。
2. 视图构建边界的 panic 恢复：某一区域构建时 panic，能否只让该区域显示故障说明、其余界面与状态照常（ADR 0006「尚未验证」第 4 项）。
3. 隐藏标题栏后的拖动区域与双击缩放（§15 第 3 项的 macOS 部分）。
4. 系统通知与点击通知后定位到对应会话（§15 第 5 项）；须打包为 `.app`。
5. 关闭最后一个窗口后重新打开，恢复草稿、所选会话、阅读位置与面板宽度（§15 第 7 项的界面状态部分）。
6. VoiceOver 实际朗读（ADR 0006「尚未验证」第 3 项），需用户手动确认。

不在本票：Windows 上的全部项目（[17 号票](17-windows-presentation-validation.md)）；真实 Agent 的同连接多会话并发（ADR 0005，需真实 ACP 适配器与调用费用，另行安排）；长会话滚动锚定（界面方案注明留待产品实现）。

## Answer

macOS 上均成立，不需要修正界面方案或 ADR 的方向，只需补充约束。证据见 [`prototypes/workbench-shell`](../../../prototypes/workbench-shell/README.md)。

1. **同窗口工具面板：可行。** 面板 WebView 是独立渲染进程；`ui.Split` 调整宽度，窗口缩放时面板宽度不变；焦点可在原生 UI 与面板之间往返；面板死循环时工作台流式输出不受影响（发布→构建平均 4.3 ms），结束渲染进程后重新载入约 0.1–0.4 s 恢复。
2. **区域级 panic 边界：可行。** 在区域外层元素的 `Children` 闭包内 recover，`List` 行与 `Overlay` 内的 panic 都只影响所在区域，重试可恢复。限制：出错那一帧显示一次半截内容；边界不放在主题作用域内部；只覆盖视图构建。已写入 ADR 0006。
3. **标题栏、通知定位、读屏：** 用户手动确认通过（通知须打包为 `.app`）。
4. **关窗重开：** 用户决定关闭最后一个窗口时**销毁窗口**，应用留在后台。宿主持有的所选会话、草稿、阅读位置、面板宽度均恢复；焦点与选区不恢复；工具面板页面随窗口重建。
5. **新约束（F17.5）：** 收起面板或隐藏窗口时 WKWebView 节流页面计时器，销毁窗口则页面结束，能力包的后台工作必须在包进程中运行，面板页面只负责展示。已补入 ADR 0005 第 5 节。

Windows 上的同类项目仍由[桌面候选在 Windows 的关键验证](17-windows-presentation-validation.md)承接；真实 Agent 的同连接多会话并发仍未验证。
