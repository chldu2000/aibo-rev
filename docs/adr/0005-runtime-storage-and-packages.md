# 进程部署、存储、ACP 接入、包与工具面板

用户于 2026-11-11 在 [11 号票](../../.scratch/aibo-rev-architecture/issues/11-module-and-desktop-architecture.md) Q85–Q110 中做出以下决定。除 Q86 外均采纳推荐；Q86 采用补充说明后修正的方案。前提是 [ADR 0003](0003-desktop-and-ui-stack.md)（MyGO、Go 宿主）、[ADR 0004](0004-presentation-protocol.md)（公开呈现协议），以及 03、04、05、07、08、09、10 号决议。

## 1. 进程部署（Q85–Q89）

- **单一应用进程。** 运行核心与桌面宿主在同一个 Go 进程中：MyGO 主线程负责窗口与原生交互，运行核心在独立 goroutine 中运行。运行核心的 Go 包不得引用 MyGO，保留以后拆分进程的可能。WebView 内容由系统在独立进程中渲染，界面故障不连带运行核心。宿主原生层崩溃时，按 03 号决议在重启后恢复状态、不自动恢复执行。
- **单实例与后台运行。** 使用 `RequestSingleInstanceLock`；注册 `OnWindowAllClosed`，最后一个窗口关闭后应用留在后台，Windows 经托盘、macOS 经 Dock 重新打开。明确退出走 `OnBeforeQuit` 的确认与停止流程；系统注销无法取消退出，只保存恢复信息。
- **Agent 进程划分。** 每个“Agent 包 + 工作区 + 影响进程环境的启动配置”一个 ACP 连接进程，同一键下的会话共用。Agent 包可声明每会话独立进程，用于同一连接并发多会话不可靠的 Agent。强制结束前的确认须列出同一进程中会被一同中断的会话。
- **子进程随应用结束。** Agent 与能力包进程随 Aibo 进程结束：Windows 用 Job Object，macOS 用进程组与父进程退出检测。重启时核对并清理残留进程。
- **能力包在独立子进程中运行**，由宿主按需启动和监督，不限实现语言。
- ~~**手动恢复入口。** 应用菜单与托盘菜单常驻“重新载入界面”“切回默认界面”……~~ 2026-11-11 取消（[ADR 0006](0006-native-ui.md)）：工作台改为原生界面，没有可重新载入的页面或可切回的默认界面。界面故障的处理见 ADR 0006“后果”；工具面板的故障处理见第 5 节。
- **子进程清理的实现（2026-11-11 验证补充）。** macOS 没有父进程退出信号：子进程读 stdin、EOF 即退出可覆盖 ACP Agent 的典型情况，但不读 stdin 的子进程与孙进程会残留。每个子进程以独立进程组启动，记录进程组号与启动时间；重启时核对后按进程组结束残留进程（[`mygo-validation`](../../prototypes/mygo-validation/README.md#子进程q87)）。

## 2. 存储与索引（Q90–Q96）

| 方面 | 决定 |
| --- | --- |
| 业务库 | 单个 SQLite 库，WAL 模式；纯 Go 驱动（如 `modernc.org/sqlite`），保持无 cgo；宿主内单一写入 goroutine，读取可并发 |
| 大内容 | 消息正文与普通工具结果入库；图片、附件及超过阈值（初始 256 KiB）的工具输出存为内容寻址文件（SHA-256）。先写临时文件、落盘、改名，再在数据库事务中登记；未登记文件由 10 号决议的 24 小时回收清理 |
| 历史搜索 | 独立索引库中的 SQLite FTS5，trigram 分词；少于 3 字的查询在所选范围内做有上限的扫描；按业务库提交序号追赶，损坏时删除并从业务库重建 |
| 流式提交 | 按 100 ms 或 64 KiB 合并提交；回合结束、工具完成、审批出现等边界立即提交；提交后才发布给界面。参数按测量调整 |
| 数据目录 | macOS `~/Library/Application Support/Aibo`，Windows `%LOCALAPPDATA%\Aibo`；首版不可更改，只保留开发用环境变量覆盖。目录内分业务库、索引库、内容文件、包程序、包私有状态、诊断日志 |
| 文件搜索 | 不持久化索引；用 Go 按需并发扫描，遵循忽略规则；文件名列表内存缓存，靠文件监视失效 |
| 格式升级 | 启动时按版本顺序迁移，迁移前 `VACUUM INTO` 生成副本；失败则保留原库、显示错误与日志位置、不进入工作台；旧版应用拒绝打开更新版本的库。副本在下一次成功启动后清理 |
| 诊断日志 | 独立的结构化日志文件，按 10 号决议的 14 天 / 100 MiB 总预算轮转 |

具体驱动在实现时以真实负载核实性能与 FTS5 trigram 支持。

## 3. ACP 接入（Q97–Q102）

- **协议库。** 从官方 schema 生成 Go 类型，自写 stdio 上的 JSON-RPC 连接层；不依赖社区 Go SDK。连接层负责先落库再发送、区分已发送未结算、按连接代际拒绝迟到结果，并保留未识别字段的原文。
- **会话控制。** 每个 Aibo 会话一个控制 goroutine，串行处理用户命令与 ACP 事件；状态变更先写库再对外动作。长时间的 prompt 请求在独立 goroutine 中等待，结果作为消息送回，取消、审批和状态接收不被阻塞。不引入通用事件总线。
- **投递证据。** 投递尝试连同连接代际与请求 ID 先写入业务库，再调用 `session/prompt`；连接断开时仍未结算的尝试标为结果未知，不自动重发（07）。
- **厂商扩展映射。** 正式支持组合（Codex、Claude）的映射是宿主内置的 Go 模块，按适配器版本选择。其他 Agent 包如需映射，可在启动入口包一层转换代理进程，对宿主只说标准 ACP 与 Aibo 扩展。
- **只读补读。** 定义 Aibo 命名空间下的只读 ACP 扩展方法（子历史、任务输出等），参数含原生身份、范围与游标，结果含完整性标记与缺口；由内置映射或转换代理实现，未实现时界面说明“不可补读”。不用可能触发执行的 load/resume 替代。
- **进程启停。** Agent 进程只在需要执行时启动（新建会话、用户明确发送或恢复）。首版不做空闲回收；进程持续到应用退出、工作区移除或信任撤销、Agent 包变更，或用户主动断开。阅读历史、搜索与准备引用不启动 Agent。
- **进程意外退出。** 不自动重启。同进程中的会话标为连接已断开，未结算投递标为结果未知；用户对某个会话选择“重新连接”时才启动新进程（新连接代际），只加载用户明确恢复的会话，并提示 Agent 可能因此继续执行（UI-LIFE-01）。

## 4. 包与 MCP（Q103–Q107）

- **交付格式。** zip 包（如 `.aibopkg`），根目录含 `aibo-package.json` 清单：包身份、版本、宿主接口兼容范围、目标平台、贡献列表（Agent / 工具 / 上下文 / 工具面板 / 呈现）、命令入口、依赖与私有状态版本。安装时校验内容哈希，解压到数据目录下按“包身份/版本”区分的目录；升级候选装入独立版本目录，不覆盖当前启用版本。
- **私有状态**存放在数据目录中按包身份与状态版本区分，不放在卸载时删除的程序目录（09）。
- ~~**语言运行时。** 宿主不内置 Node 等运行时。包自带可执行文件，或在清单中声明外部依赖，由检查说明缺失，不自动下载。官方 Agent 包把基于 Node 的适配器编译为单文件可执行文件。~~（2026-11-15 由 [ADR 0009](0009-official-agent-packages-and-node-runtime.md) 取代：官方 Agent 包为单个 JS 文件，Node 先用用户已有的，或由用户操作下载最新 LTS 版供 Aibo 使用；不带 CLI。）
- **命令入口。** 清单声明三类命令：启动（Agent 包的 ACP 进程、能力包的服务进程）；检查（输出 JSON：已满足 / 缺失 / 未知及指引，不得创建或恢复原生会话）；迁移私有状态（输入旧状态副本与版本号，输出新状态目录，宿主在临时目录中运行并设超时，成功且校验后才切换）。未声明检查命令时结果为“未知”。
- **能力包接口。** 能力包是 stdio MCP 服务器：工具用 MCP tools，可选上下文用 MCP resources 与资源模板，Aibo 特有元数据放在 `_meta`。宿主作为 MCP 客户端连接各包，再统一对 Agent 暴露。工具面板经 ADR 0004 的公开协议访问宿主。
- **工具调用与身份。** 宿主为每个 Aibo 会话提供一个 MCP 端点，聚合宿主内置工具（引用读取、只读补读）与该会话可用的能力包工具，经 `session/new`/`session/load` 的 `mcpServers` 传给 Agent。Agent 支持 HTTP MCP 时用 `127.0.0.1` 端点、凭据放请求头；否则用 Aibo 程序自身的桥接模式（stdio ↔ 宿主本地连接）、凭据放环境变量。凭据绑定会话、连接代际与工作区，换代、撤销信任或卸载包时立即失效；每次调用由宿主校验授权并记录活动。

## 5. 工具面板（Q108–Q110；2026-11-11 由 Q114 修订）

> **2026-11-11 修订。** 实测 iframe 不能调用 Go，且与工作台同线程、死循环会卡死工作台（[`mygo-validation`](../../prototypes/mygo-validation/README.md#工具面板iframe-不可行独立-webview-可行)）。Q114 改为：每个面板是原生工作台窗口中嵌入的一个 WebView（`Window.NewWebView`），在独立渲染进程中运行；页面由宿主经自定义协议从包目录提供，每个包一个协议 host（独立 origin）；顶层页面直接经受限的绑定访问宿主（ADR 0004 第 8 节）。下文中的“iframe”均按“面板 WebView”理解，实例范围不变。故障处理补充：
>
> - 页面卡死时 `Reload()`/`LoadURL()` 不能恢复。macOS 的已验证方式为先结束该面板的渲染进程再载入；Windows 按下述 ADR 0008 修订处理，不使用 `Page.ProcessID()` 结束面板。
> - 面板心跳在面板创建与页面就绪时重置，避免收起后重新展开时因旧心跳过期误报。
> - 面板页面中的输入法判断以 `isComposing`（或 `keyCode 229`）为准，不依赖组合事件的先后。
>
> **2026-11-12 补充（18 号票，[`workbench-shell`](../../prototypes/workbench-shell/README.md)）。** 收起面板或隐藏窗口时，WKWebView 会大幅节流页面计时器（收起 3 秒仅约 1/6）；关闭最后一个窗口时销毁窗口（用户决定），面板 WebView 随窗口销毁，重新打开窗口时按实例范围重建面板。因此 F17.5 的后台工作只能在包进程中运行，面板页面只负责展示，重建后从包进程取回状态；不能依赖页面脚本在收起或关窗期间持续运行。

- ~~**装载方式。** 每个面板是一个 iframe，每个包使用独立 origin；页面由宿主经自定义协议从包目录提供。~~ 2026-11-11 改为嵌入的独立 WebView，见上方修订。面板用自己的客户端连接与受限凭据访问宿主（ADR 0004 第 8 节），不能读取未发送草稿或代替用户发送。不沿用旧 `toolView` 合同。
- **实例范围。** 每个“包 + 工作区”一个面板实例。同一工作区内切换会话不重建面板，面板经受限接口读取当前会话身份并订阅变化；切换到其他工作区时销毁旧实例，包进程中的工作继续（F17.5）。
- **收起与故障。** 收起只隐藏面板 WebView。加载失败、握手超时或心跳超时时，面板区显示错误与“重新加载面板”，只重建该面板，不触发整套呈现回退、不影响会话执行。Windows 的共享浏览器故障按下述修订处理。包进程退出时面板显示进程已停止，“重新加载”同时重新启动包进程。

**2026-11-12 Windows 修订（[ADR 0008](0008-windows-tool-panel-recovery.md)，用户已确认）：**

- WebView2 的面板 renderer 独立，但浏览器进程共享；`Page.ProcessID()` 返回共享浏览器 PID，不得用于结束单个面板。
- renderer 崩溃可先尝试 Reload；面板无响应时，经心跳识别并由用户选择“重新加载面板”，销毁并重建该 WebView，释放原 renderer，不枚举或强杀进程。
- `browser-exited` 时标记全部受影响面板失效；用户重新加载时，销毁并重建这些 WebView。保留原生窗口、会话执行和包进程，并按包与工作区恢复展示状态。
- 不能仅依赖 `unresponsive` 回调发现无响应；本次死循环 12 秒内未观察到该回调。重建不代替用户发送消息，也不重启 Agent。

## 依据

各项依据与被否决的选项记录在 11 号票对应问题中。共同的取舍原则：

- 主目标是降低维护成本（[ADR 0002](0002-aibo-refactor-direction.md)）：不拆出不必要的进程与协议，不维护社区库的适配，不内置语言运行时（2026-11-15 修订为按需下载 Node，见 ADR 0009），不引入通用事件总线。
- 恢复状态与恢复执行分开（03、07）：进程退出或连接断开后，宿主不自动重启 Agent、不自动重新加载会话、不自动重发。
- 宿主掌握授权与证据（07、09、10）：工具调用经宿主端点，投递先落库，迁移在副本上进行，大内容先落盘再登记。

## 尚未验证

这些是实现前或实现中的必做验证，结果若推翻某项选择，须新开 ADR 取代对应部分：

- ~~WKWebView 与 WebView2 中跨 origin iframe 是否在独立进程中运行……~~ 2026-11-11 在 macOS 上验证：iframe 与主页面同线程、不能调用 Go；改用嵌入的独立 WebView（第 5 节修订）。每个包的独立 origin 已验证。WebView2 的独立 origin 与 renderer 隔离已由 17 号票验证，恢复修订见 ADR 0008。
- 纯 Go SQLite 驱动在长历史与并发流式写入下的性能，以及 FTS5 trigram 支持。2026-11-11 在 macOS 上验证通过（`modernc.org/sqlite` v1.62.0：并发流式写入约 28 万行/秒，FTS5 trigram 可用，见 [`mygo-validation`](../../prototypes/mygo-validation/README.md)）。
- 正式支持的 Agent 在同一连接中并发多个会话的可靠性；不可靠的 Agent 改为声明每会话独立进程。2026-11-12 Codex（codex-cli 0.167.0 + `@agentclientprotocol/codex-acp` 2.6.0）验证可靠：一个连接 6 个会话并发、各自工作目录、取消互不影响，适配器退出时 app-server 随之退出（[`acp-concurrency`](../../prototypes/acp-concurrency/README.md)，19 号票）。2026-11-12 用户决定正式版本先支持 Codex 与 Claude Code；Claude Code 由 [20 号票](../../.scratch/aibo-rev-architecture/issues/20-acp-same-connection-concurrency-claude-code.md)验证。
- Windows Job Object 与 macOS 父进程退出检测在应用崩溃时确实结束全部子进程。2026-11-11 macOS 部分已验证：须用“stdin EOF + 重启时按进程组清理”（第 1 节补充）；Windows 部分于 2026-11-12 由下文三组 Job Object 实验验证。
- ~~页面心跳中断与 Windows `unresponsive` 事件的提示……~~ 2026-11-11 随全局恢复入口取消；Windows 上工具面板 WebView 的卡死与恢复并入 [17 号票](../../.scratch/aibo-rev-architecture/issues/17-windows-presentation-validation.md)。

2026-11-12 Windows 验证（17 号票已由自动证据与用户人工确认收口）：

- Job Object：专用宿主在创建后代前加入 KILL_ON_JOB_CLOSE 的 Job Object；正常退出、Stop-Process -Force、taskkill /F 三组中，事先确认存活的四类子孙进程全部结束。见 [win-children-result.json](../../prototypes/mygo-validation/reports/win-children-result.json)。这补齐上文 Windows 子进程清理项的原型证据，不代替产品接线验收。
- WebView2：不同包为不同安全 origin，renderer 独立但共享浏览器。renderer 死循环时另一面板可用；结束 renderer 后 Reload 可恢复。共享浏览器退出会同时影响两面板，Reload 无效；重建 WebView 可恢复。直接重建死循环面板也已验证原 renderer 退出、另一面板不受影响。心跳仍必要：本次 12 秒观察内未出现 unresponsive 回调。见[原始报告与限制](../../prototypes/workbench-shell/reports/win-validation-progress.md)。恢复合同由已接受的 [ADR 0008](0008-windows-tool-panel-recovery.md)补充。
