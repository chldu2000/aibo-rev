# 默认界面改用 MyGO 原生 UI，取消外部完整呈现包

用户于 2026-11-11 在 Q112–Q114 中全部采纳推荐：

| 问题 | 决定 |
| --- | --- |
| Q112 默认界面技术栈 | 用 MyGO 原生 UI（`github.com/egoist/mygo/ui`，Go）编写，流式 Markdown 与代码高亮用 `ui/markdown`。放弃 Svelte 5、Bits UI、virtua、markdown-it、Shiki 与前端构建链 |
| Q113 外部完整呈现包（05 号决议） | 取消。只保留内置原生界面；用户通过设计令牌（主题）与设置定制。F20.4–F20.7 不再是必需项 |
| Q114 能力包的工具面板 | 每个面板是原生窗口中嵌入的一个 WebView（`Window.NewWebView`），在独立渲染进程中运行，顶层页面可直接调用 Go，只能访问为它开放的受限范围。取代 ADR 0005 Q108 的 iframe 方案 |

桌面容器（MyGO）与宿主语言（Go）不变。

## 依据

- **实测更好。** [`prototypes/native-ui`](../../prototypes/native-ui/README.md) 用原生 UI 实现了会话流与输入区，覆盖 [`stream-composer`](../../prototypes/stream-composer/README.md) 验证过的交互。真实窗口中帧耗时中位 0.9 ms，流式“发布 → 下一次构建”平均 5.4 ms（WebView 原型为“发布 → 下一帧”平均 9 ms）。10,000 条历史只构建可见行。用户手动确认了中文输入法、粘贴截图、拖入文件、跨消息复制、流式期间向上滚动与深浅色切换。
- **维护成本更低**（[ADR 0002](0002-aibo-refactor-direction.md) 的主目标）。界面、宿主与运行核心同为 Go，没有 Node 构建链，没有页面与宿主之间的协议。
- **外部完整呈现包与原生 UI 不能共用实现**（Q113）。宿主不能从包中装载 Go 代码；若保留外部包，就要同时维护原生界面与 WebView 呈现两条路径，每项交互做两遍，并各自通过全部验收。这与主目标冲突。
- **工具面板必须由包独立交付**（Q114）。原生面板只能编译进宿主。[`mygo-validation`](../../prototypes/mygo-validation/README.md) 证实 iframe 不可行：iframe 不能调用 Go，死循环会卡死父页面。同一原生窗口中的第二个 WebView 在独立进程中运行，面板卡死或被结束不影响工作台。

## 模块与状态

原先跨框架的“公开呈现协议”不再需要，ADR 0004 只保留状态归属与工具面板协议两部分（见该文的 2026-11-11 修订）。

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| 运行核心 | 会话、ACP、投递、存储（ADR 0005） | 不引用 MyGO |
| 交互层 | 草稿、附件与引用选择、审批与追问的作答、提交进度、错误；共通呈现状态的保存与恢复；向界面提供只读视图模型与命令 | 运行核心；不引用 MyGO `ui` |
| 界面包 | 用 MyGO `ui` 构建窗口内容；只经交互层读写（UI-GEN-01） | 交互层、MyGO `ui` |
| 桌面宿主 | 窗口、菜单、托盘、单实例、工具面板 WebView 与其受限协议 | MyGO |

- **线程。** 视图在 MyGO 界面线程上构建；其他 goroutine 的变化经 `Window.Update` 投递后才修改界面读取的状态。重计算（高亮、搜索、大文本处理）不在界面线程上进行（UI-STREAM-05）。
- **草稿。** 保留 ADR 0004 §5 的保存时机：停止输入约 400 ms 后、失焦、切换会话、发送前保存；输入法组字期间不保存。多个窗口编辑同一草稿时，仍按版本号拒绝过期写入。
- **令牌。** `docs/design/tokens/tokens.json` 仍是唯一来源，生成 Go 令牌（界面包使用）与 `tokens.css`（宿主提供给工具面板，建议面板使用）。
- **定制。** 用户可选配色与深浅色（F20.3）；组件外观由设计令牌与 Aibo 自身的组件封装决定，不提供运行时替换界面。

## 后果

- **界面故障不再与运行核心隔离。** 原生界面与运行核心在同一进程：界面代码 panic 会结束整个应用，界面线程卡死时窗口无响应。前者按 03 号决议在重启后恢复状态、不自动恢复执行；后者只能退出后重启。因此要求：界面线程上不做阻塞工作；界面包在构建视图的边界上恢复 panic、写诊断日志并显示错误，而不是让应用退出。这一点在实现时验证。
- **不再有“重新载入界面 / 切回默认界面”入口与页面心跳**（ADR 0005 §1 的手动恢复入口）。工具面板保留自己的故障处理（ADR 0005 §5 修订）。
- **验收工具改为 Go。** `tools/ui-checks` 用 Go 重写：令牌与对比度检查保持不变，原 CSS 规则改为对界面 Go 源码的检查，验收用例改用 MyGO 的无窗口测试器 `ui.Tester`，按无障碍角色与名称定位元素（[界面硬性要求](../design/ui-requirements.md) §0、§11）。
- **组件外观需要单独调整。** 原型只用了默认组件加令牌颜色；按钮、下拉选择等的外观之后单独设计（用户 2026-11-11）。

## 约束

1. 运行核心与交互层不得引用 MyGO `ui`；界面包不得直接引用运行核心、ACP 连接层或存储。
2. 锁定 MyGO v0.9.0 与其要求的 Go 1.27.3，`CGO_ENABLED=0`；升级须经过真实流程回归。
3. 默认界面须满足[界面硬性要求](../design/ui-requirements.md)，并通过 `go -C tools/ui-checks run . all`。
