# 共享交互状态与公开呈现协议

用户于 2026-11-11 在 [11 号票](../../.scratch/aibo-rev-architecture/issues/11-module-and-desktop-architecture.md) Q72–Q84 中全部采纳推荐，决定共享无界面交互模块的位置与实现语言，以及公开呈现接口的传输方式与数据格式。前提是 [ADR 0003](0003-desktop-and-ui-stack.md)（MyGO + 系统 WebView、Go 宿主）和 [05 号决议](../../.scratch/aibo-rev-architecture/issues/05-presentation-interface.md#answer)（框架中立、单一完整呈现包、换包后恢复共通呈现状态、默认呈现使用同一公开接口）。

## 决定

### 1. 状态的位置（Q72）

- 权威状态与需要恢复的交互状态由 **Go 宿主**持有，包括已保存的草稿、附件与引用选择、审批与问题的作答、提交进度、错误，以及其他共通呈现状态。呈现崩溃或换包后，这些状态不丢失。
- 页面侧只有**框架无关的薄客户端**，负责：合并订阅数据、保存正在编辑的本地值、焦点/选区/IME 等 DOM 辅助。它不做业务推导。

### 2. 协议与传输（Q73–Q76）

- 公开呈现接口是**自有的版本化业务协议**，经少数通用 MyGO 绑定入口承载（如一个查询/命令入口、一个订阅入口）。宿主内部的 Go 服务方法**不得**直接 `Bind` 给呈现包。
- 持续更新：**每个订阅占一次 `mygo.Channel` 调用**，按序推送、有背压，页面关闭即取消。`Event` 不承载业务数据，最多用于窗口级通知。
- 编码：**JSON**，配明确的 schema。要引入二进制编码，须先有测量数据证明 JSON 不够用。
- 图片、附件：经 **MyGO 自定义协议 URL** 读取。URL 只对当前呈现实例和允许的读取范围有效，消息里只放引用和元数据。长正文分段读取。不得把大对象 base64 嵌入消息。

### 3. 客户端与类型（Q77–Q78）

- 运行时客户端由宿主经自定义协议**按协议版本提供**（如 `/_aibo/sdk/v1/client.js`），这是唯一的运行时来源，呈现包不得把它打包进自身。客户端为纯 ES 模块，不依赖任何框架。
- 另发布一个 npm 包，只含类型定义和开发用的模拟宿主，供呈现包作者做类型检查和脱离宿主开发。
- 类型权威是一个**独立的 Go 协议包**，它不得引用宿主内部类型；由它生成 JSON Schema 与 TypeScript 类型。CI 对比 schema 快照，不兼容的变化必须升协议主版本。

### 4. 订阅与增量（Q79–Q80）

- **工作台订阅**：每个呈现实例一个，推送会话列表、通知和全局状态。
- **会话订阅**：每个打开的会话一个，推送尾部窗口、状态条，以及待处理的审批和问题。会话关闭或切走即取消。
- 更早的历史不进入订阅，经**游标分段查询**读取，对应虚拟列表的向前加载。
- 订阅先发快照，之后发增量。增量有三种：按实体 ID **整条替换**、**删除**、流式正文**追加**。每条增量带单调递增的序号，客户端发现缺口就请求新快照。

### 5. 本地编辑同步（Q81）

- 草稿在停止输入约 400 ms 后保存到宿主；失焦、切换会话、发送前、页面隐藏时立即保存；IME 组合输入期间不保存。
- 宿主按草稿版本号拒绝过期的写入，防止两个窗口同时编辑时旧值覆盖新值。

### 6. 版本协商（Q82）

- 宿主同时支持**当前和上一个协议主版本**。呈现包在清单中声明所需的主版本与最低次版本，握手时确定使用哪个版本。
- 次版本只能新增可选字段、新的实体类型和新的命令；客户端必须忽略不认识的字段和实体。
- 没有可用版本时，按 05 号决议明确失败，自动回退到默认呈现并说明原因。

### 7. 框架适配（Q83）

- 不发布官方框架适配包。客户端的订阅接口采用 `subscribe`/`getSnapshot` 形状，可直接接入 React `useSyncExternalStore`、Svelte `createSubscriber`、Vue `shallowRef` 等；文档给出各框架几行代码的接入示例。
- 默认呈现的 Svelte 适配留在默认包内部，不是公开接口。

### 8. 工具面板（Q84）

- 能力包的工具面板复用同一客户端、传输与编码，但握手时授予的能力范围受限：只能访问所属能力包的数据、当前工作区与会话的少量只读信息，以及明确开放的命令（如“向输入框添加附件或引用”）。
- 面板不得读取未发送的草稿，也不得代替用户发送（[界面方案 §8](../design/ui-interaction.md)）。

## 依据

- 状态放在宿主，所有框架共用一份实现，换包和崩溃后的恢复由此自然成立；正在输入的文字留在页面，不必每次按键往返。前序跨框架原型（React、Vue 共用宿主状态，经版本化快照 + 增量、缺口重同步）验证过这一形态。
- 自有协议让外部呈现包依赖长期合同，不随宿主内部重构变化，也为版本协商和拒绝失效实例的请求提供落点。
- `Channel` 的按序、背压、随页面取消与呈现实例的生命周期一致；`Event` 没有背压。大对象走协议 URL，不会堵住订阅流，也不会撞上约 1 MiB 的积压上限。
- 以 Go 类型为源，schema 与 `encoding/json/v2` 的实际输出不会不一致；从 JSON Schema 生成 Go 代码的工具较弱。
- 整条替换幂等、合并简单，外部包不必理解业务规则。
- 不维护多套框架适配包，回应降低维护成本的主目标（[ADR 0002](0002-aibo-refactor-direction.md)）。
