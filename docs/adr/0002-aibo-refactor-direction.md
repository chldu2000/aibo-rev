# 以现有 Aibo 为基线推进彻底重构

用户明确将 aibo-rev 的后续方向定为现有 Aibo 的一次彻底重构。Aibo 已具备日常 vibe-coding 所需的多项能力，本阶段先盘点功能、架构职责及运行数据，承接已有可用行为与修复经验，降低长期维护成本并治理冗杂数据。

终端优先、原生 CLI 配合 GUI 阅读及 VS Code 扩展不再是当前产品主线；TUI 到 GUI 的通用转换暂不考虑。此前文档保留为历史备选，避免把终端路线的具体交互和引用时点直接套入现有 GUI 工作台。

先形成[功能范围清单](../refactor-feature-inventory.md)与[数据生命周期清单](../data-lifecycle-inventory.md)，逐项区分已实现、部分实现和规划功能，再确定保留、调整及交付阶段。用户尚未逐项批准功能删减、技术栈替换、旧合同兼容范围或旧库清理；本次方向决定也不要求所有代码从零重写。

重构应将数据治理作为主线：业务历史、恢复与投递证据、必要审计、可重建索引、过程与诊断明细分别定义责任及保留规则。已有可靠治理机制需要评估复用，不能因“冗杂”而直接删除仍承担业务职责的记录。
