# 终端路线引用固定版本的原始 Transcript

当前主线已改为现有 Aibo 的彻底重构，见 [ADR 0002](0002-aibo-refactor-direction.md)。以下是终端路线语境下曾确认的决定；原始 transcript、固定版本和摘录规则仍可作为重构参考，但不能未经核对就替代现有 Aibo 的历史与引用合同。

用户提出以跨 Agent 会话引用为核心的新候选路线：直接运行各 Agent 的原生 CLI，尽量保留会话列表及 Git、文件浏览等面板的扩展性。已确认的引用设计允许运行能力与完整引用能力分离，接受少量历史接入适配，以减少统一聊天界面和输入流程的维护工作。本决定记录产品约束，不表示已选择终端引擎或批准产品实施。

## 已确认的取舍

- 点击引用时冻结历史，不要求捕获原生 CLI 的实际提交时点。来源后续变化通过用户主动更新引用纳入。
- 可运行的 Agent 与支持完整会话引用的 Agent 分开定义。没有可靠历史入口的 CLI 仍可运行，需要手动导入后才能引用历史。
- 传递来源 Agent 的原始 transcript，保留其格式与内容；不以屏幕滚动记录或生成摘要代替。
- 默认附带最近几轮原文，保留关联工具记录，并设总大小上限；用户可以选择全文。具体轮数、大小预算和超限呈现规则尚未确定。
- 摘录和完整按需读取必须指向同一个固定版本。完整内容可通过 MCP 等方式提供，不能在后续读取时偷偷换成来源文件的最新内容。
- 引用插入目标原生 CLI 的输入框，由用户检查并发送；不自动模拟 Enter。尚未验证输入框粘贴兼容性的 Agent 提供复制入口。

## 代价与边界

这一选择减少对原生输入状态、提交 Hook 和统一消息渲染的依赖，代价是引用不会自动追踪来源最新消息，各 Agent 的原生交互仍有差异。

“完整”指已捕获的 transcript 范围，不暗示可以获得厂商未记录的历史、附件文件字节或恢复原生执行状态。按轮次摘录可能需要每种格式的小型读取适配器；可以建立定位索引，但不要求先把所有原始记录转换成统一聊天模型。

来源仍在写入时的捕获边界、引用保留与删除规则、MCP 调用身份与访问范围、具体容器及技术栈仍待设计和验证。
