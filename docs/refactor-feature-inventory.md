# Aibo 完整版本功能 Checklist

本清单服务于[已确认的重构方向](adr/0002-aibo-refactor-direction.md)。目标是恢复一份可核对的产品基线，随后决定实现边界和交付顺序；不是对旧目录、旧合同或旧表结构逐一复制。

## 勾选方式

- `[x]` 表示你认为“一个完整版本”必须包含该特性，**不表示已经实现或验收完成**。
- `[ ]` 表示尚未选为必需项，不代表决定删除。所有项目初始留空，由你手动标记。
- 每个编号对应一个可独立讨论的功能点，可直接在后面补充范围或备注。
- 本清单是范围选择的唯一勾选入口；数据专项文档保留现状和验收说明，不另设一份重复选择。
- 功能选定后，权限校验、状态隔离、数据完整性等正确性要求随功能一同成立，不能作为可省略的附加项。

## 盘点基线与状态

2026-11-01 只读检查相邻 `aibo`、`aibo-plugins` 仓库的代码、合同与专项文档。Aibo HEAD 为 `de70665`，分支为 `docs/lightweight-architecture-proposal`；工作区存在既有未提交改动，本次未修改该仓库。源码中宿主版本为 0.1.1、宿主 SDK 为 0.1.13，不把版本滞后的文档索引作为唯一依据。

“已有”表示存在实现及接线证据，不等于本轮重新验收；“部分”表示支持取决于 Agent、平台或仅完成某些阶段；“规划”不算既有交付。下列阶段安排是建议，用户尚未逐项决定删除或延后某项已有功能。

## 日常使用闭环

打开项目 → 选择 Agent → 创建/恢复会话 → 输入消息与附件 → 处理工具活动、审批和追问 → 排队/取消 → 检查变更与 Git → 引用到另一会话 → 重启后找回历史并继续工作。

首个可替换版本应证明这条完整链路可用，而不是分别展示几个能启动的模块。

## 不能误算为已交付的能力

- 完整源码编辑器、IDE 语言服务或完整文件管理器：现有代码证明的是任务配置和文件预览，不能仅凭名称判定已有。
- 所有 Agent 都能导入/恢复任意原生会话：当前有提供者专项入口，不能泛化成全平台通用能力。
- 所有 Agent 的完整子任务过程：已有接入的详细程度不同；主会话读取工具也不自动包含子任务全文或附件文件字节。
- 完整 Agent 管理中心：原生配置写入、账户切换/登录挑战、原生扩展管理及后台管理操作尚未全面实现。
- 按 Git 仓库/归档 URL 安装、深链接、自动更新与签名体系：[分发计划](../../aibo/docs/sdk-and-plugin-distribution.md)明确 D2–D4 未实施。
- 全部原始事件已能安全清理、完整数据管理 GUI、任意旧库已验证迁移压缩：现有治理只覆盖部分条件，见数据盘点。
- 全平台原生稳定性：已有多平台代码和构建不等于完成各系统验收，既有证据主要覆盖 macOS arm64。
