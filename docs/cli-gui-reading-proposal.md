# 原生 CLI 执行与 GUI 历史阅读方案

状态：历史备选，尚未选定实施；当前主线为[现有 Aibo 的彻底重构](adr/0002-aibo-refactor-direction.md)。它在[终端优先提案](design.md)上增加 GUI 历史阅读能力，下文的引用规则仅对应当时的[终端路线决定](adr/0001-terminal-transcript-references.md)。

## 核心分工

原生 CLI 负责与 Agent 的实时执行交互；GUI 负责会话目录、已保存 transcript 的阅读、搜索和引用。两个视图关联同一个来源会话，不启动两份 Agent 对话，也不建立第二套执行状态机。

| 操作 | 负责的界面 |
| --- | --- |
| 输入提示、slash command、模型与模式选择 | 原生 CLI |
| 工具审批、回答追问、取消任务 | 原生 CLI |
| 阅读已保存消息、代码块、折叠工具记录 | GUI 历史视图 |
| 搜索、定位原文、复制、创建引用 | GUI 历史视图 |
| 查找会话、打开终端、查看归档历史 | GUI 会话目录 |
| Git、文件浏览、Diff | 工作区扩展面板 |

历史视图对 Agent 执行保持只读，不表示整个工作台不能写入会话名称、引用等管理数据。历史中的审批或追问是记录；真正等待处理的交互在 CLI 完成，不能把历史文本变成有效的审批按钮。

## 界面组织

同一个会话提供“原生终端”和“阅读历史”两个标签，也可允许左右分屏。切换或隐藏视图不应结束正在运行的 Agent；停止进程和关闭展示应分别设计。

```text
┌─────────────────────────────────────────────────────┐
│ 工作区                         Git / 文件 / 设置     │
├───────────────┬─────────────────────────────────────┤
│ 会话列表       │ 会话 A                              │
│               │ [原生终端]  [阅读历史]              │
│ A · Agent X   │                                     │
│ B · Agent Y   │ 当前视图：完整 CLI 或 GUI 历史       │
│ C · Agent X   │                                     │
│               ├─────────────────────────────────────┤
│ 搜索历史       │ 引用 / 导出 / 查看来源               │
└───────────────┴─────────────────────────────────────┘
```

原生终端保留完整 CLI 区域，不通过屏幕布局解析把原生输入框拆出并伪装成 GUI Composer。若要求输入、审批和追问都改为统一 GUI，需要另行采用结构化交互接入，其维护范围超出本方案。

## 历史读取与展示

会话桥从可靠的原生 transcript、导出或可用 Hook 获取记录，识别消息角色、顺序、工具关联和更新关系。GUI 可以展示消息列表、Markdown、代码块和可折叠工具记录；未知类型提供原始记录查看入口，保留来源定位。

展示模型与搜索索引是原文的派生数据。适配器只需提供阅读与定位所需信息，不必实现所有工具的专门卡片或理解 Agent 内部调度。解析仍有格式维护成本，不能承诺任意 Agent 零适配；没有可靠历史入口时沿用手动导入。

历史视图可跟随已保存 transcript 更新，但它可能落后于 CLI 实际执行。界面应标明最近同步状态和实际读取范围，不能根据落盘历史推断 Agent 此刻是否正等待审批、已经停止或仍有未保存输出。终端滚动文本不作为完整历史来源。

## 阅读与引用的数据关系

阅读视图可持续更新，已创建的引用保持固定。GUI 排版不改变引用原文：即使工具记录在界面中折叠，引用仍按摘录规则保留相应原始记录。

一个典型流程是：

1. 用户在会话 A 的原生 CLI 中请求 Agent X 分析问题。
2. 打开阅读历史，浏览回复并搜索相关文件名。
3. 点击引用到会话 B，在该时刻捕获 A 的固定 transcript 版本。
4. 将来源说明、原文摘录和完整读取入口插入 B 的原生 CLI 输入框；不兼容时复制。
5. 用户检查、补充任务要求并发送。
6. Agent Y 如需更多历史，通过 MCP 等机制读取同一固定版本的完整内容。

引用与当前阅读版本的关系应明确展示。若阅读后来源又发生变化，引用以点击时实际捕获的版本为准；不能把旧阅读画面声称为新快照的完整预览。跨文件或仍在更新的记录如何一致捕获，需要技术验证。

## 会话目录与扩展面板

目录项保存会话身份、来源 Agent、工作区、历史位置及可用的恢复信息，与终端实例分离。已有实例时打开对应终端；支持原生恢复时可重新启动；无法恢复时仍可阅读和引用已保存历史。具体恢复行为需按 Agent 验证，不能由目录项存在推断可恢复。

搜索针对已收集的历史及定位索引，结果打开 GUI 原文位置，无需为了查看旧消息而启动 Agent。索引重建、去重和流式记录更新属于历史读取模块。

Git、文件浏览和 Diff 等面板围绕工作区独立运行，无需接管 Agent 聊天协议。扩展合同、会话删除与历史保留规则仍沿用主提案中的待定项。

## 收益与代价

相比完整 GUI 聊天客户端，本方案不重新实现 Agent 的全部命令、执行交互、审批和配置表单。CLI 新增功能通常可以继续在终端使用，GUI 阅读适配可以独立演进。

相比仅提供终端和引用入口，本方案新增了 transcript 展示、搜索、同步状态及定位维护。用户需要在操作与阅读视图间切换，GUI 历史可能延迟，复杂原生记录未必能立即获得精细展示。它不承诺所有原生功能都能从统一 GUI 操作。

## 验证重点

- 两个不同 Agent 的原生会话能可靠关联到各自 transcript，不因切换视图混入另一会话。
- 隐藏终端、打开历史及切换会话不改变 Agent 的执行状态；活动审批仍在正确的 CLI 中可达。
- transcript 迟写、更新、记录不完整和未知类型时，GUI 明确展示同步状态并保留原文。
- 搜索结果能够回到正确记录；展示与索引不会改写 transcript。
- 来源继续变化后，原文摘录和 MCP 全文读取仍对应同一固定引用版本。
- 用户可以顺畅完成“终端执行 → GUI 回顾 → 跨 Agent 引用”，并评估视图切换是否值得其阅读收益。

上述均为候选方案的验收目标，尚未执行；终端引擎、桌面技术栈、具体同步机制及首批 Agent 未定。
