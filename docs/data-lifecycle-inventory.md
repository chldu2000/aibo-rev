# Aibo 重构数据生命周期盘点

依据 2026-11-01 源码、迁移与专项规格的只读调查。没有打开用户实际运行库、执行清理或测量当前磁盘占用；文档中的历史 GB 级采样不作为本轮数据规模或可回收量。

本文保留旧版实现证据与当时的候选治理范围。2026-11-04 已确认的新架构责任及初始默认值见[持久数据、搜索与诊断的所有权](../.scratch/aibo-rev-architecture/issues/10-data-ownership-and-search.md#answer)；不能将下列旧表结构、配额和维护工具直接视为新架构选型或交付范围。所选功能的内部正确性及已确认的无主托管资产回收，与完整数据管理产品分开判断。

## 先区分数据承担的职责

| 类别 | 现有例子 | 重构要求 |
| --- | --- | --- |
| 用户业务历史 | messages、turns、subagent_messages、附件/引用、会话与工作区、草稿 | 历史在插件不可用时仍可读；保留/删除按明确业务生命周期 |
| 执行与恢复 | 原生绑定/recovery、队列、turn_delivery、process_runs、权限及恢复操作 | 小型必要状态；活动操作和结果未知不能按普通日志到期淘汰 |
| 授权及操作事实 | 审批、能力调用、工程任务、工作区写入、插件升级/迁移 | 独立保存身份、授权、目标、结果和因果关联，减少对全部原包的依赖 |
| 过程与协议明细 | capability_events、agent_events、消息分片、进度、重复快照 | 完整结果可靠保存且业务引用解除后，才有资格有界保留/压缩 |
| 派生索引 | search_documents、FTS、search_file_state、展示定位索引 | 可重建，源数据与索引生命周期分离 |
| 观察状态与统计 | observation_states、observation_changes、observation_days | 保存最新状态、真实变化和有界统计，不让无变化轮询无限生成永久明细 |
| 文件与插件资产 | 插件包、plugin-data、剪贴板图片、产物、检查点、升级备份 | 明确归属及引用；私有文件可能是恢复必需状态，不能统一视为缓存 |
| 应用诊断日志 | logs 内 JSONL、应急日志 | 与业务和恢复分离，限制字段、大小和期限；日志失败不影响业务 |

## 已证实的多份持久化路径

[Capability Broker](../../aibo/src-tauri/src/capability_broker.rs) 将流事件写入 capability_events；[会话投影](../../aibo/src-tauri/src/session_projection.rs) 又将正文/推理/工具结果写入 messages，并保存 agent_events；搜索触发器进一步生成搜索表示。

同一业务内容存在多份持久表达有代码依据，但不能直接推导所有副本都可删除。原始事件仍可能承担审批、上下文重置、恢复、去重或调用链依据。需要先把这些必要事实分离，再判断原包可保留多久。

## 已有治理与剩余范围

| 已有治理 | 证据及限制 |
| --- | --- |
| 0066 移除能力原始事件的搜索副本 | [事件存储策略](../../aibo/docs/event-storage.md)；并未删除所有原始事件 |
| 独立序号高水位 | 0067；避免清理事件后用剩余最大序号分配新事件 |
| 独立子 Agent 最新完整历史及回填 | 0069、[历史与回填](../../aibo/src-tauri/src/event_retention.rs)；旧原包仍需通过资格验证 |
| 成功无变化观察的折叠 | [观察结算](../../aibo/src-tauri/src/observation_settlement.rs)；按可信合同与实际输入分类，不是凡 read 都可删除 |
| 观察统计清理 | [统计保留](../../aibo/src-tauri/src/statistics_retention.rs)；90 天/32 MiB，分批执行 |
| 合格子 Agent 重复快照清理 | 0076、[诊断明细保留](../../aibo/src-tauri/src/diagnostic_retention.rs)；正常 24 小时/128 MiB、明确失败 7 天/128 MiB，仍有完整投影及未决责任保护 |
| 后台维护接线 | [event_retention](../../aibo/src-tauri/src/event_retention.rs) 与宿主启动路径；不代表所有事件类别已覆盖 |
| 应用文件日志 L1 | [日志实现](../../aibo/src-tauri/src/diagnostics.rs)与[验收记录](../../aibo/docs/diagnostic-logging-validation.md)；10 MiB 分片、14 天/100 MiB 总预算，受控字段和目录入口 |
| 小型 recovery 与独立任务存储 | [恢复状态规格](../../aibo/docs/session-recovery-state-spec.md)；源码已实现，不应继续当成未修复的内联任务膨胀问题 |
| 维护命令源码 | [storage_maintenance](../../aibo/src-tauri/src/storage_maintenance.rs)及[aibo-storage](../../aibo/src-tauri/src/bin/aibo-storage.rs)；inspect/prepare/clean/compact 不等于已交付完整用户级数据管理与正式库演练 |

上述诊断明细配额与应用文件日志配额属于不同数据域，不能相加后宣称全应用磁盘硬上限。受保护数据、索引、SQLite 页、WAL 和空闲页需分别计量。

## 重构应落实的功能

产品范围选择统一在[完整版本功能 Checklist](refactor-feature-inventory.md)的 F23 数据管理与迁移中勾选；下表保留对应的候选验收问题，不表示全部已选。内部数据责任以本篇开头所链接的当前决议为准。

| 编号 | 功能 | 验收要回答的问题 |
| --- | --- | --- |
| D01 | 数据分类与所有权 | 每项数据为何保存、谁生产和读取、是否权威、何时不再需要？ |
| D02 | 只读占用分析 | 能否区分业务/恢复/审计/过程/索引/文件，以及逻辑占用、WAL 和空闲页？ |
| D03 | 写入去重与观察聚合 | 无变化轮询和重复快照是否还导致永久数据线性增长？重要变化是否仍可追溯？ |
| D04 | 原始事件有界保留 | 是否已证明完整结果与必要证据独立存在？哪些类别仍受保护？超额时如何报告？ |
| D05 | 搜索与索引重建 | 索引删除或损坏后能否恢复，且不影响源历史、消息定位和引用？ |
| D06 | 附件与资产生命周期 | 图片、产物、检查点、插件私有状态和升级备份是否能按引用安全回收？ |
| D07 | 历史与引用保留 | 引用是否持有独立内容，来源删除后怎样处理，用户能否知道可读范围？ |
| D08 | 备份、迁移与恢复 | 能否在副本预览迁移、验证内容等价，失败续跑或回退，避免隐式重发操作？ |
| D09 | 物理空间维护 | 逻辑清理后是否需要独立压缩？维护前备份、应用占用检查和中断行为是否明确？ |
| D10 | 独立诊断与支持导出 | 日志是否有界、可定位故障且不承担业务恢复？L2 临时诊断/导出是否纳入首版？ |

原盘点建议把 D01、D03、D04、D05 和必要恢复规则融入新写入路径，并在迁移前准备占用分析、迁移与物理维护工具。当前决议已明确所选功能的数据责任；该建议不自动纳入全部工具和 GUI。旧版数据迁移的交付范围仍由[架构验收与旧版切换的承诺](../.scratch/aibo-rev-architecture/issues/12-architecture-acceptance-and-transition.md)单独确认。

## 尚未完成或不能直接复用的保证

- 任意消息分片、推理和工具原包的完整性证明与通用清理；0075 正文修复不等于所有相关原包都可删除。
- 重复失败聚合、结果未知调用的结算，以及覆盖所有事件类别的保留机制。
- 日志 L2 的临时 DEBUG 与诊断包导出；事件保留规格中的详细采集开关与日志 L2 不应混为同一功能。
- 正式数据升级、清理和物理压缩的最终完整演练；已有专项通过不能代替完整目标验收。

删除 SQLite 行主要释放内部可复用空间，文件变小还涉及独立的 checkpoint/VACUUM 维护，不能把逻辑回收量直接称为磁盘文件缩减。
