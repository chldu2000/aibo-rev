## 1. 设计原则

1. **状态如实。** 请求不等于生效。“已发送停止”“已暂停目标”“已投递”在得到证据前都显示为进行中或未确认，不用乐观的成功态。这是本界面与一般聊天客户端最大的区别，优先级高于简洁。
2. **一处一事实。** 回合、队列、目标、后台任务各有自己的状态位置和控制，不合并成一个“运行中/停止”开关。按钮名称相似的动作，旁边标明它影响的范围。
3. **不可用要说明原因。** Agent 缺能力、工作区未信任、配置未确认等情况下，入口保留为禁用态，悬停或聚焦时说明原因和解决办法。只在入口与当前任务完全无关时才隐藏。
4. **阅读优先。** 会话流是主体；当前会话的控制件集中在输入框及其上方的状态条，不在消息流里散布全局操作，也不另设常驻的会话检视栏。
5. **键盘可达。** 所有主要流程都能只用键盘完成；中文 IME 组字期间按 Enter 不会发送。
6. **克制。** 中性灰阶加一种强调色；状态色只用于状态，不当装饰。动效只用来表达状态变化，并遵循“减少动态效果”系统设置。

## 2. 视觉语言

### 2.1 色彩

令牌以语义命名，呈现包可以覆盖；下面是主要颜色，完整取值以 [tokens.json](tokens/tokens.json) 为准。2026-11-10 为使状态色作 12px 文字时达到 4.5:1，浅色的 `attention`、`success`、`unknown` 已加深。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `bg` | `#FBFBFA` | `#151517` | 会话主区背景 |
| `surface` | `#F3F3F1` | `#1B1B1E` | 侧栏、工具面板区 |
| `raised` | `#FFFFFF` | `#222226` | 卡片、输入框、弹层 |
| `border` | `#E3E3DF` | `#2C2C31` | 1px 分隔线 |
| `text` | `#1C1C1A` | `#E7E7E4` | 正文 |
| `text-muted` | `#6A6A65` | `#9A9AA0` | 次要文字，对比度 ≥ 4.5:1 |
| `accent` | `#4C5BD4` | `#8C97FF` | 主操作、选中态、焦点环、链接 |
| `running` | 同 `accent` | 同 `accent` | 执行中 |
| `attention` | `#966319` | `#E0A748` | 需要用户处理：审批、追问、队列暂停 |
| `danger` | `#C93B3B` | `#F07070` | 失败、保存故障、破坏性操作 |
| `success` | `#297C4D` | `#5CC48A` | 已完成（只在需要区分完成与空闲时使用） |
| `unknown` | `#8357BD` | `#B490F0` | 结果未知、未确认：投递未知、停止未确认 |

“结果未知”单独用紫色，配合虚线描边和 `?` 标记，不与失败或需要处理混用，因为用户对它的处置不同：不能直接重试，要先核实。

配色选择（F20.3）只替换 `accent`，提供 6 个预设，状态色固定。主题提供 浅色 / 深色 / 跟随系统 三档。

### 2.2 字体与密度

- 界面：`-apple-system, "Segoe UI Variable", "Segoe UI", "PingFang SC", "Microsoft YaHei UI", sans-serif`。
- 等宽：`"SF Mono", "Cascadia Code", "JetBrains Mono", Menlo, Consolas, monospace`。
- 字号：界面 13px，会话正文 14px / 行高 1.6，辅助信息 12px。**最小字号 12px。**
- 控件高度：28px（紧凑）/ 32px（输入框内的主操作）。指针命中区域至少 24×24px（WCAG 2.2 AA）；行内图标按钮以内边距扩大命中区域，图形本身可以更小。
- 间距基数 4px；圆角 6px（控件）/ 8px（卡片、弹层），不使用切角。
- 会话正文最大宽度 760px，在主区居中；窗口最小 960×600。

### 2.3 状态标记

会话列表、状态条和消息内统一使用同一套小标记（8px 圆点或 14px 图标），每个标记都配有文字或可读的 `aria-label`，不能只靠颜色区分。

| 标记 | 含义 |
| --- | --- |
| 实心强调色圆点 + 缓慢呼吸 | 当前回合或目标正在执行 |
| `attention` 圆点 | 等待用户：审批、追问、队列因失败或取消而暂停 |
| `danger` 圆点 | 回合失败、关键保存失败 |
| `unknown` 虚线圆圈 + `?` | 投递结果未知、停止未确认 |
| 无标记 | 空闲 |
| 右侧数字徽标 | 未发送队列项数 |

### 2.4 避免的样式

- **不使用左侧信号条**（用户 2026-11-10）。卡片、列表项、提示块、引用块不用一侧加粗的彩色边条来表达状态或选中；这类样式带有明显的“AI 生成界面”痕迹。只有所采用的 UI 库或设计系统明确规定时才例外，并在实现中注明出处。
- 替代做法：
  - **状态卡片**（审批、追问、失败、结果未知）：整圈 1px 边框使用状态色的弱化版本，配合同色浅底、标题图标与文字着色；“结果未知”用整圈虚线。
  - **列表选中**（会话列表、菜单、候选项）：只用背景填充，必要时加粗文字；不加左侧竖条。
  - **用户消息**：使用聊天气泡（§5.2），不用竖线区分。
- 结构性的中性分隔线不受此限，例如面板之间的 1px 分隔、折叠层级的 1px 中性引导线。

## 3. 窗口与信息架构

```
┌──────────────┬──────────────────────────────────────────┬────────────┬──┐
│ ● ● ●     ＋ │ 会话标题  工作区     ● 执行中 · 2:14  Agent ⋯ │ 插件面板     │⎇ │
│ [搜索 ⌘K]    │──────────────────────────────────────────│ （可收起，   │▣ │
│ ▾ aibo-rev   │                    ┌──────────────────┐  │  默认收起）  │  │
│   会话 A 📌 ● │ Agent 回复（无气泡）  │ 用户消息（右侧气泡） │  │            │  │
│   会话 B  ?2 │                    └──────────────────┘  │            │  │
│   会话 C     │ [审批卡 · 就地出现在会话流中]                │            │  │
│ ▸ mygo  🔒   │──────────────────────────────────────────│            │  │
│              │ ⚠1 个审批  ◎目标·推进中  🤖子Agent 1  ≡队列 3   │            │  │
│ 已归档        │ ┌ 输入框 ─────────────────────────────┐   │            │  │
│ ⚙ 设置        │ └───────────────────[插话][排队/发送]┘   │            │＋│
│              │ 模型 · 推理 · Fast · 权限模式   上下文 38%   │            │  │
└──────────────┴──────────────────────────────────────────┴────────────┴──┘
```

- **标题栏。** macOS 隐藏系统标题栏，红绿灯按钮放在侧栏左上角，侧栏顶部的空白区可以拖动窗口。Windows 在主区右上角保留系统窗口按钮（WebView2 的非客户区由 MyGO 窗口选项处理，须在 Windows 上验证拖动区和贴靠布局）。
- **侧栏（240px，可调 200–360，`⌘B` 收起）。** 工作区与会话目录、全局搜索入口、归档、设置。
- **会话视图（自适应）。** 会话头、会话流、**状态条**（§8.1）与输入区。目标、子 Agent、后台任务和队列都以状态条上的标签进入，不占用独立的栏。
- **工具面板区（右侧）。** 最右是 44px 宽的图标栏，列出已安装的能力插件提供的面板；点击后在左边展开 360px 面板（可调 280–560），再点一次收起。`⌥⌘I` 切换上次使用的面板。没有任何插件提供面板时，整个区域不出现。窗口宽度低于 1180px 时面板自动收起。详见 §8.2。
- **会话详情。** 原“上下文”信息默认不展示，从会话头 `⋯` 菜单或点击上下文占用打开（§8.3）。
- **设置。** 替换会话视图的全页视图，侧栏保留；`Esc` 或左上角“返回”回到原会话，阅读位置不变。
- **命令面板 / 全局搜索（`⌘K`）。** 居中浮层，是唯一的全局检索入口。

所有面板尺寸、收起状态属于默认包的**包私有呈现状态**，按包保存。草稿、所选附件和引用、阅读位置、展开状态、焦点和选区属于**共通呈现状态**，以会话或条目的稳定身份记录，换包后恢复。

## 4. 侧栏：工作区与会话目录

### 4.1 结构

1. 顶部：搜索按钮（显示 `⌘K`）、新建会话按钮（`⌘N`）。
2. 工作区分组，可折叠。分组标题显示名称；未信任时带锁形标记。悬停显示路径，右键或 `⋯` 菜单提供：新建会话、信任设置、在 Finder/资源管理器中显示、移除工作区。
3. 分组内的会话默认按最近活动排序；**置顶**的会话排在分组顶部（多个置顶之间同样按最近活动排序），行内显示图钉标记。每行：状态标记、标题（单行省略）、置顶标记、未发送队列数字徽标、Agent 小图标。
4. 底部：“添加工作区”、“已归档”（进入归档列表视图）、设置、主题快速切换。

### 4.2 交互

- 单击切换当前会话；`⌘1…9` 切换到前九个可见会话；`⌃Tab` / `⌃⇧Tab` 在最近使用顺序中切换。
- 双击标题或按 `F2` 就地改名。`Enter` 确认，`Esc` 取消。
- 会话行菜单：置顶 / 取消置顶、改名、归档、复制会话信息。**没有“关闭会话”。**
- 会话的“最近活动”指用户发送、排队投递或 Agent 产生新内容的时间；只是切换查看不改变排序，避免列表在阅读时跳动。
- **归档**：没有活动时直接归档，并显示 5 秒的“撤销”提示。有活动（回合、目标、后台任务）时弹出确认框，列出这些活动，提供“停止后归档”与“取消”；停止得到确认后才真正归档。未发送队列保留并标记为暂停。
- **移除工作区**：规则同归档。确认文案写明“保留业务历史、项目文件和暂停的队列；可在搜索中按‘已移除’来源找到历史”。
- 归档列表视图与普通列表结构相同，行内提供“取消归档”。归档会话可以阅读、搜索，不能发送；输入区替换为“取消归档后继续”。

### 4.3 新建会话

`⌘N` 或 `+` 打开一个轻量弹层，不跳转页面：

1. 工作区（默认当前工作区）。
2. Agent 列表：每项显示名称、适配器版本、验证状态（`已验证` / `未验证组合`），以及可执行文件和认证检查结果（F02.6）。检查失败的 Agent 可以选中查看原因，但“创建”按钮禁用，同时提供“打开 Agent 设置”。
3. 可选：初始模型与权限模式；默认沿用该 Agent 的全局默认值。
4. `Enter` 创建。会话立即出现在列表顶部，焦点进入输入框。Agent 进程可以在首次发送时再启动；启动中在会话头显示“正在连接 Agent…”。

工作区未信任时，弹层顶部显示信任说明与“信任并继续”。

## 5. 会话视图

### 5.1 会话头（44px）

左侧：标题（可点击改名）、工作区名。右侧依次为：

- **Agent 标识**：名称 + 验证状态。未验证组合显示小号 `未验证` 标签，悬停说明“此 Agent/适配器组合可用，但不在正式支持范围内”。
- **运行状态文字**：例如“执行中 · 2 分 14 秒”“等待审批”“停止未确认”。点击定位到对应位置（审批卡、恢复卡，或打开状态条上的对应浮层）。
- **`⋯` 菜单**：置顶、改名、会话详情、归档。

### 5.2 会话流

按时间顺序排列的结构化条目，按类型渲染：

| 条目 | 呈现 |
| --- | --- |
| 用户消息 | **右对齐的聊天气泡**（最大宽度 78%，右下角小圆角），气泡内显示正文、附件缩略图、引用卡片；插话消息加 `插话` 标记和强调色描边。气泡下方右对齐一行小字显示**投递状态**：`已排队` → `投递中` → `已接收`。结果未知时显示 `unknown` 样式与“结果未知 · 核实 / 重新发送（可能重复执行）” |
| Agent 消息 | 不加气泡，占满正文宽度，便于阅读长回复与代码；Markdown 渲染；代码块带语言标签与“复制”；文件路径以等宽显示（文件预览未纳入范围，不做可点击跳转） |
| 思考摘要 | 默认折叠为一行“思考 · 12 秒”，展开显示提供者公开的摘要，字色为 `text-muted` |
| 工具调用 | 单行卡片：图标、工具名、目标摘要（命令/路径）、状态、耗时；展开显示参数与结果，长输出折叠并提供“展开全部”。连续多个只读工具调用合并为“读取了 6 个文件”组，可展开 |
| 审批请求 | 见 §7；在流中就地呈现，失效后转为只读的历史记录 |
| 追问 / 表单 | 见 §7 |
| 子 Agent | 单行卡片“子 Agent · 名称 · 状态”，点击在主区打开其只读详情（§8.1） |
| 模式转换 | 系统行：“Agent 请求切换到 计划模式”，需要确认时以审批卡呈现 |
| 失败 | `danger` 边框卡片：失败原因（可定位的部分加粗）、原始错误可展开复制；操作为“重试” “跳过并继续队列”。队列因此暂停时在卡片里写明 |
| 缺口 / 截断 | 虚线分隔行：“此处有 3 条记录未能保存（应用中断）”或“工具输出已截断，保留前 12,000 字符” |
| 重启恢复点 | 横向分隔：“应用于 11-04 09:12 重启 · 此前回合未确认结束” |

**流式与滚动。** 内容在可靠保存后批量出现，不逐字闪烁。用户位于底部时自动跟随；向上滚动后停止跟随，底部出现“↓ 有新内容”胶囊按钮。切换会话后恢复该会话的阅读位置。

**长会话。** 条目按稳定 ID 分段加载；向上滚动到顶端时加载更早内容，滚动位置不跳动。搜索命中跳转时先加载命中段，再高亮命中条目 2 秒。

**复制与选区。** 支持跨条目选择文本；消息悬停时右上角提供“复制原文（Markdown）”和“引用到…”。

### 5.3 输入区

```
┌───────────────────────────────────────────────────────────┐
│ [#队列与投递测试 · 固定 14:32 · 近3轮 · 9.8k ▾] [@src/core/] [🖼 截图.png ×] │
│ 继续实现队列的暂停与恢复，参考上面引用的讨论…                          │
│                                                           │
│ [📎] [@] [#] [/]                         引用 9.8k/32k  [插话 ⌘⏎] [排队 ⏎] │
└───────────────────────────────────────────────────────────┘
  Claude Opus ▾   推理 高 ▾   Fast ○   权限 询问 ▾        上下文 38% · 76k/200k
```

**输入与触发符**

- `@`：工作区文件和目录（F06.1–F06.2），模糊匹配，遵循忽略规则。选中后生成路径 chip，提示文字为“按路径引用，发送时读取当时内容”。
- `#`：会话引用（F07.1–F07.2）。列出同工作区的会话，显示 Agent 和最近活动时间；可以引用正在运行的会话。
- `/`：Agent 原生命令和 Skills（F04.9），以及少量 Aibo 命令（如 `/goal`）。条目注明来源（Agent / Skill / Aibo）。当前 Agent 不提供命令发现时，列表显示该原因。
- 粘贴图片或拖入图片生成图片 chip（F06.3–F06.4），可以只发送图片。拖入文件夹或非图片文件转为路径 chip。
- 弹出列表用 `↑↓` 选择、`Enter`/`Tab` 确认、`Esc` 关闭；chip 可用 `←`/`Backspace` 选中后删除。

**引用 chip（固定版本）**

- 加入时即固定版本，chip 显示：来源标题、固定时间、范围（默认“近 3 轮”）、字符量。来源未完成时加一个 `未完成` 标记。
- 点击展开菜单：范围（近 N 轮 / 全文）、**更新到最新版本**（显示新增的轮数）、预览摘录、移除。
- 来源在固定之后有新内容时，chip 上出现一个小圆点，提示可以更新；**不会自动刷新**。
- 单条超过 12,000 字符或合计超过 32,000 字符时，计量变为 `attention` 色，并说明超出部分会按省略标记截断，可以改为全文，由 Agent 按需读取。
- 接收 Agent 不支持全文读取工具时，“全文”选项禁用并说明“仅能附带摘录”。

**发送按钮的状态**

| 会话状态 | `Enter` 主按钮 | `⌘Enter` 次按钮 | 其他 |
| --- | --- | --- | --- |
| 空闲 | **发送** | — | — |
| 执行中 | **排队**（进入队列，状态条“队列”标签数字 +1） | **插话**；Agent 不支持时禁用，悬停说明原因 | 输入框右侧出现 **停止**（`⌘.`） |
| 队列已暂停 | **排队**，旁边显示“队列已暂停 · 恢复” | 同上 | — |
| 未信任工作区 | 输入区替换为信任提示（§10.1） | — | 草稿仍可编辑 |
| 必要设置未确认 | 禁用，提示“正在应用模型设置…”或失败原因 | — | 不会按旧值悄悄发送 |
| 归档 | 替换为“取消归档后继续” | — | — |

IME 组字期间（`isComposing`）的 Enter 只用于确认候选词。`Shift+Enter` 换行。

**执行设置栏（F08）**

位于输入框下方的一行下拉控件：模型、推理强度、服务档位（Fast）、权限模式，以及右侧的上下文占用。

- 选项来自 Agent 实际返回的可用值。某项不支持时显示为禁用的灰色文本并说明原因，不隐藏。
- 修改后显示“应用中”（`unknown` 色细下划线），Agent 确认后恢复正常；失败则回退并提示原因。说明文字写明：**设置在下一次投递时生效，不影响正在进行的回合，也不改写已排队消息的内容。**
- 上下文占用以文字加细进度条显示，点击打开“会话详情”查看明细（§8.3）。Agent 未报告时显示“未报告”，不显示 0%。

## 6. 运行控制：停止、队列、插话

### 6.1 停止当前执行

`⌘.` 或停止按钮。这是组合动作（[08 Q48](../../.scratch/aibo-rev-architecture/issues/08-goals-and-background-work.md#answer)），界面分别显示各部分的结果：

1. 会话头立即显示“正在停止…”（`unknown` 色）。
2. 会话流中的停止条目逐项显示：
   - 当前回合：`停止请求已发送` → `已停止` / `未确认`
   - 未发送队列：`已暂停（3）`（宿主可以立即确认）
   - 持续目标：`暂停请求已发送` → `已暂停` / `未确认`；不支持暂停时显示“此 Agent 不支持暂停目标，目标可能继续推进”。
   - 后台任务：**不受影响**，写明“后台任务不随此操作停止，可在状态条的“后台任务”中单独取消”。
3. 超过 10 秒未确认时，会话头显示“停止未确认”，给出“继续等待”和“查看详情”两个选项。不提供“视为已停止”。

### 6.2 队列（状态条“队列”浮层）

有未发送项时，状态条出现“队列 N”标签：推进中为普通样式，暂停时为 `attention` 色并附“· 已暂停”，含结果未知项时为 `unknown` 虚线样式并附“· 结果未知”。点击打开浮层，内容如下：


- 列表头：状态（推进中 / 已暂停：原因）、**暂停/恢复**、**清空**（需确认，只删除未开始投递的项）。
- 每个队列项：正文前两行、附件和引用摘要、入队时间。悬停时显示操作：**立即发送**、编辑（未开始投递时，取回到输入框）、删除；支持拖动排序。
- **立即发送**（F09.5）：空闲时直接发送该项。忙时，如果 Agent 支持插话，则以插话方式发送；不支持时弹出确认“停止当前执行后发送此条？”，并说明其余队列保持暂停。只处理选中项。
- 已开始投递的项不能删除，操作变为“查看投递状态”。
- **结果未知**的项以 `unknown` 样式置顶，显示“投递结果未知（连接在发送中断开）”。操作为“重新发送（可能重复执行）”，并需要二次确认；新尝试在原项下方缩进显示，原记录保留。
- 队列因失败或取消暂停时，列表头使用 `attention` 色，写明原因，并提供“恢复队列”。恢复队列不会恢复目标，反之亦然，按钮旁的说明文字写明这一点。

### 6.3 插话

`⌘Enter` 或“插话”按钮把当前输入作为插话发出。插话消息在会话流中标注 `插话`。如果宿主确认插话未被消费且控制状态仍允许，会自动转为一次普通投递，并在消息下注明“插话未被采纳，已作为下一条消息发送”。如果结果未知，显示 `unknown` 状态，不自动补发。

## 7. 审批与追问

### 7.1 审批卡

```
┌ ⚠ 需要审批 ──────────────────────────────────────────┐
│ Bash   pnpm test --filter core                        │
│ 工作目录 ~/Workspace/aibo-rev                           │
│ ─────────────────────────────────────────────────── │
│ [1 允许一次]  [2 本会话始终允许]  [3 拒绝]   [拒绝并说明…] │
└──────────────────────────────────────────────────────┘
```

- 在会话流中就地出现，以 `attention` 色的整圈细边框和浅底色标出（不使用左侧信号条，见 §2.4）。状态条最左侧同时出现 `attention` 色标签“1 个审批待处理 ⌘⇧A”，点击滚动到最早的待处理请求并聚焦，让用户在任何滚动位置都能看到。
- 选项完全来自 Agent 提供的选项，按原顺序显示，宿主不改名、不合并。数字键 `1–9` 对应选项，前提是焦点在审批卡上，或输入框为空时按 `⌘⇧A` 聚焦到最早的待处理审批。
- 提交后按钮立即锁定，并显示“已提交：允许一次”，确认后变为只读记录。传输结果未知时显示 `unknown` 状态与“核实”，不允许再选一次。
- 失效的请求（回合结束、连接更替、应用重启）转为灰色的只读历史，写明“此请求已失效（连接已重建）”，**不恢复为可操作按钮**。
- 多个审批同时待处理时按到达顺序排列，状态条标签显示数量。
- 会话列表中该会话显示 `attention` 标记。窗口未聚焦时发送系统通知（受设置中的通知开关控制）。

### 7.2 追问与表单（F05.3）

- 选择题：单选或多选列表，支持数字键选择，`Enter` 提交。
- 表单：按 Agent 提供的字段类型渲染（文本、多行、选择、布尔）。必填项在提交时校验并就地提示。
- 正在填写的答案属于共享交互状态：切换会话或重载呈现后保留，**不会自动提交**。
- 可以“跳过此问题”（如果 Agent 允许取消单个追问），这与“停止当前执行”是两个分开的操作。

### 7.3 模式转换（F05.4）

Agent 请求切换模式时，以审批卡呈现，标题为“切换到计划模式？”，选项照 Agent 原样显示。切换生效后，执行设置栏的权限模式随之更新，会话流中插入一条系统行。

## 8. 状态条、工具面板区与会话详情

### 8.1 状态条（输入框上方）

当前会话中所有“在后台进行、需要随时看到”的事物，以一行标签显示在输入框正上方。没有内容时整行不出现。外部呈现包可以换用其他形式，但必须展示同样的信息和状态区分（05 补充）。从左到右：

| 标签 | 出现条件 | 样式 | 点击 |
| --- | --- | --- | --- |
| `N 个审批待处理` / `N 个问题待回答` | 有有效的审批或追问 | `attention` | 滚动并聚焦到最早的请求（`⌘⇧A`） |
| `目标 · 推进中/已暂停/…` | 会话有持续目标 | 状态圆点；请求未确认时为 `unknown` 并带转圈 | 打开目标浮层 |
| `子 Agent N` | 有子 Agent 记录 | 有执行中的项时附呼吸圆点 | 打开子 Agent 列表浮层 |
| `后台任务 N` | 有后台任务记录 | 同上 | 打开后台任务列表浮层 |
| `队列 N` | 有未发送项 | 见 §6.2 | 打开队列浮层 |

**浮层规则**

- 浮层在输入框和状态条上方展开，宽度与输入框一致，最大高度为窗口的 46%，内容可滚动。同一时间只打开一个浮层；再次点击同一标签、点击 `×` 或按 `Esc` 收起。浮层展开时会话流相应缩短，不遮挡审批卡。
- 切换会话时浮层收起；标签对应的内容消失（例如队列清空）时浮层自动收起。
- 输入框焦点不因打开浮层而丢失，草稿不受影响。

**目标浮层（F11）**

- 目标文本、状态（推进中 / 已暂停 / 等待条件 / 已完成 / 失败，均以 Agent 报告为准）、开始时间、预算与用量。
- **预算与用量**：逐项显示 Agent 报告的数值和单位，并标明来源，例如“Token 58k / 200k（Agent 报告）”。未报告的项显示“未报告”，不显示 0，也不用会话总用量代替。
- 操作：暂停 / 恢复 / 清除，按能力启用。每个按钮的说明文字写明影响范围：“只暂停目标，不停止当前回合和队列”。清除需要确认，并说明“不删除已有历史和引用”。
- “恢复目标”属于执行意图：应用重启后需要用户明确点击，不会自动恢复。
- **创建目标**：没有目标时状态条不显示目标标签。通过 `/goal` 命令（输入框 `/` 列表中标注来源为 Aibo）打开设置目标的对话框。Agent 不支持目标时，该项在列表中显示为不可用并说明原因。

**子 Agent 与后台任务（F12）**

- 浮层内为列表：名称或命令、状态、耗时。同一个原生活动既是子 Agent 又在后台运行时，只列一次，并加上 `后台` 标签。
- 点击列表项，**在主区打开详情**，替换会话流并隐藏输入区，顶部有“← 返回会话 › 子 Agent · 只读”。`Esc` 返回，并恢复原会话的阅读位置。
  - 子 Agent 详情：它自己的消息和工具记录，渲染方式与主会话流相同。内容不完整时显示“仅有状态信息，Agent 未提供过程记录”，或者提供“读取完整记录”按钮（只读补读，触发后保存）。
  - 后台任务详情：状态、开始时间、最后输出时间、输出流（等宽，自动跟随，可暂停跟随），以及“取消任务”（需确认，写明只取消这一个任务，实际影响以 Agent 报告为准）。取消请求后显示“取消请求已发送”，直到 Agent 报告结束。
- 会话流中的子 Agent 卡片也进入同一个详情视图。

**队列浮层**：见 §6.2。

### 8.2 工具面板区（能力插件）

右侧区域只承载能力插件提供的界面，例如 Git、终端。默认呈现不在这里放任何会话自身的信息。

- **图标栏**：每个提供面板的插件占一个图标，悬停显示面板名和来源插件及版本；底部 `＋` 进入“设置 › 扩展包 › 能力包”。
- **面板**：标题栏显示图标、名称和收起按钮；标题下一行固定写明“由 <插件名 版本> 提供”，让用户分清哪些界面来自插件。面板内容完全由插件渲染。
- **状态**：每个工作区记住上次打开的面板和宽度，属于包私有呈现状态。面板收起或切换会话不终止插件内的工作（例如终端进程），这一点与“视图离开不结束执行”的原则一致。
- **故障**：插件面板加载失败或无响应时，只在面板内显示错误与“重新加载面板”，不影响会话视图；不触发整套呈现的回退。
- **与会话的关系**：插件面板可以通过公开接口向当前输入框添加附件或引用（例如“让 Agent 审查改动”把 diff 作为附件放入输入框），但不能代替用户发送，也不能读取未发送的草稿。

- **验收**：F17.1 由至少一个真实的面板型能力包验证安装、打开、收起、重载、故障与卸载，功能可以有限。
- **外部呈现包**：必须提供工具面板的承载位置和打开/收起入口，形式可以不同（[05 补充](../../.scratch/aibo-rev-architecture/issues/05-presentation-interface.md#2026-11-10-补充默认工作台设计带来的完整性要求)）。

面板的装载方式与故障处理见 [ADR 0005 §5](../adr/0005-runtime-storage-and-packages.md#5-工具面板q108q110)：每个包一个独立 origin 的 iframe，按“包 + 工作区”实例化，收起只隐藏，故障只重建该面板；不沿用旧 `toolView` 合同。面板访问宿主的接口见 [ADR 0004 §8](../adr/0004-presentation-protocol.md#8-工具面板q84)。

### 8.3 会话详情（默认不展示）

原先的“上下文”信息只在需要排查时打开：会话头 `⋯` › “会话详情…”，或点击输入框下方的上下文占用。以对话框呈现：

- **本会话发出的引用**：来源、固定版本、读取授权状态（有效 / 待核实 / 已撤销）。
- **上下文与用量**：上下文窗口占用、本会话 token 用量和费用（以 Agent 报告为准，未报告显示“未报告”）。
- **会话信息**：Agent 包与适配器版本、验证状态、原生会话 ID（可复制）、会话绑定状态、工作区路径。

待发送的附件和引用不再单独列出，直接在输入框的 chip 中管理和移除（F06.5）。

## 9. 全局搜索与命令面板（`⌘K`）

一个输入框覆盖 F10.2、F10.3、F10.5、F10.6、F10.7：

- 打开时显示最近会话和常用命令。输入后按分组显示结果：**命令**、**会话**、**消息**、**文件**、**Skills/Agent 命令**、**设置**、**扩展包**。
- 范围前缀：`>` 只搜命令，`#` 只搜会话，`?` 只搜消息内容，`@` 只搜文件。输入框下方的范围 chip 可点击切换，也可选“当前工作区 / 全部工作区”。
- 消息结果显示会话标题、角色、时间和带高亮的片段。来自归档或已移除工作区的结果带 `已归档` / `已移除` 标签；默认包含这些结果，可以用筛选排除。
- 文件结果遵循忽略规则；结果区底部说明“已跳过 12 个二进制/无法读取的文件 · 包含隐藏文件”。
- `Enter` 执行或跳转：会话直接切换；消息切换会话后定位并高亮；文件结果插入当前输入框作为 `@` 引用（文件预览未在范围内）；设置项打开对应设置页并高亮该项。
- 索引重建中时，结果区顶部显示“索引更新中，结果可能不完整”。

## 10. 信任、生命周期与恢复

### 10.1 工作区信任（F01.2）

- 打开未信任的工作区：可以阅读历史、搜索、管理会话目录。输入区替换为提示块：“此工作区尚未信任。信任后 Aibo 才会在这里启动 Agent，并向 Agent 提供文件和引用读取。” 按钮为 **信任此工作区**、**仅阅读**。草稿仍然可以编辑并保存。
- 撤销信任（工作区菜单 › 信任设置）：确认框列出将被阻止的内容与正在运行的活动。确认后会话头显示“已撤销信任 · 正在停止 2 项活动”，逐项显示停止确认；队列暂停。重新信任后队列**不会自动恢复**，需要手动恢复。

### 10.2 关闭窗口与退出

- 关闭最后一个窗口：应用留在后台继续运行。第一次关闭时显示一次性提示：“Aibo 仍在后台运行 2 项活动。……”macOS 使用 Dock 图标与菜单栏；**Windows 常驻通知区域图标**，图标菜单提供“打开工作台”“重新加载呈现”“切回默认呈现”“退出”，图标上用小圆点表示有活动或待处理请求。
- 退出（`⌘Q`）且有活动时，弹出原生确认框，列出活动（会话 · 回合/目标/后台任务）。选项为“停止并退出”和“取消”。
- 选择停止后进入等待视图，逐项显示停止状态。部分项超过 10 秒未确认时，提供“继续等待”和“强制退出”。强制退出的说明写明：“这些活动可能仍在运行，下次启动时会标记为待核实。”

### 10.3 重启后恢复

- 启动后历史、草稿、队列和目标状态都恢复，但**不自动执行任何操作**。
- 如果上次退出时有未完成的活动，主区顶部显示一次恢复横幅：“已恢复上次的历史、草稿与队列。2 个会话在退出时有未完成活动，继续执行前需要你确认。” 带“查看”按钮，点击后筛选出这些会话。
- 相关会话的状态标记为 `unknown`。进入会话后，会话流底部显示恢复卡：

  > 退出时：当前回合未确认结束 · 队列已暂停（2）· 目标已暂停
  > **[恢复连接]** 仅查看
  > 恢复连接会重新启动 Agent 并加载原生会话，Agent 可能会因此继续执行。

  恢复连接后，再分别决定是否恢复队列和目标；卡片上给出对应按钮。

### 10.4 关键保存失败（F22）

- 窗口顶部出现全宽 `danger` 横幅，不可关闭：“无法写入会话历史：磁盘空间不足。已暂停新的工作，并请求停止 2 项执行（1 项未确认）。” 操作：“查看详情”（列出受影响的会话和停止状态）、“重试保存”、“打开日志目录”。
- 在此期间，发送和排队按钮禁用，说明原因；草稿编辑不受影响。
- 横幅同时区分“未能保存的内容”和“停止未确认”两项事实，不合并为一句“出错了”。

### 10.5 呈现故障与回退（F20.7）

- 外部呈现包加载失败、不兼容或崩溃时，宿主自动切回默认呈现。默认呈现启动后显示提示：“外部呈现「Compact Pro 1.2」加载失败，已切回默认呈现。草稿和阅读位置已恢复。” 操作：“查看原因”、“再次尝试该呈现”。
- 无响应时宿主**不会自动回退**。恢复入口独立于 WebView：
  - 应用菜单 › **工作台** › “重新加载呈现”（`⌘⇧R`）、“切回默认呈现”。
  - macOS Dock 菜单与 Windows 通知区域菜单提供同样的两项。
  - 原生恢复窗口（MyGO 原生 UI）：从上述菜单或重复点击 Dock 图标打开，显示当前呈现、运行中活动数，以及“重新加载”“切回默认”“打开诊断”。
- 默认呈现自身连续两次加载失败时，不再循环重试，只显示原生恢复窗口与诊断入口。

## 12. 首次使用与空态

1. **首次启动**：主区显示欢迎页，只有一个主操作“添加工作区”，下方列出检测到的 Agent 及其状态（可执行文件和认证）。没有可用 Agent 时，提供“打开 Agent 设置”。
2. **添加工作区**：系统文件夹选择器 → 信任确认（见 §10.1）→ 自动打开新建会话弹层。
3. **空会话**：会话流区域显示 Agent 名称、模型，以及三条触发符提示（`@` 文件、`#` 引用会话、`/` 命令）。不放示例提示词。
4. **空搜索结果**：说明当前范围，并给出“扩大到全部工作区”或“包含隐藏文件”的入口。

## 14. 无障碍与国际化

- 会话流使用 `role="log"`；新内容通过 `aria-live="polite"` 播报摘要，例如“Agent 回复完成”或“需要审批”，不播报流式正文。
- 状态标记都有文字替代。焦点环为 2px `accent` 外描边，不能被样式去掉。
- 弹层打开时锁定焦点，关闭后焦点回到触发元素。
- 对比度：正文与次要文字都满足 4.5:1；禁用态通过形态（虚线或降低饱和度）加文字说明表达，不只依靠变浅。
- 中英文文案长度差异：按钮宽度自适应，侧栏标题单行省略并带 `title`。时间、数字按区域设置格式化。
- 语言切换即时生效，不需要重启。

### 15.1 验证记录：会话流与输入区（2026-11-10）

用 Svelte 5 + Bits UI + virtua 实现了会话流与输入区，在 Playwright Chromium 与 WebKit 27.2 上验证；代码、运行方法与完整数据见 [`prototypes/stream-composer`](../../prototypes/stream-composer/README.md)。未在 MyGO 内运行，上面 1–7 项仍需在真实 WebView 中完成。

已确认（WebKit，10,003 条历史 + 含 3 个代码块的流式回复）：挂载 9 行；60 fps、0 个超过 50ms 的帧；发布到下一帧最大 16ms；向前加载 80 条时可见条目位移 0px；候选弹层锚定输入框且焦点不离开输入框。

实现时必须遵守的发现：

1. **代码高亮放在 Web Worker。** Shiki 首次编译语法在 JavaScriptCore 上阻塞主线程约 175ms（Chromium 约 88ms），预热无效；移入 Worker 后消失。
2. **“跟随底部”按每次 scroll 事件重新判定。** 拖动滚动条与程序定位不产生 wheel 事件，只监听滚轮会在加载更早记录时把用户拉回底部。
3. **需要说明原因的禁用控件用 `aria-disabled`**，保留焦点和提示，不用 `disabled`。
4. **触发符的查询部分允许包含 `/`**，否则 `@src/co` 这类路径不会弹出候选（静态原型已一并修正）。
5. **流式 Markdown 按语法单元切块。** 原型按空行切块会拆开松散列表，正式实现应按 markdown-it token 切块；已渲染块按内容缓存，只有最后一块随流式更新。

仍未解决：WebKit 下一次 `ResizeObserver loop completed with undelivered notifications` 提示（Chromium 无），不影响行为，来源未定位；中文 IME、WebView2、剪贴板图片、拖放与屏幕阅读器未测。
