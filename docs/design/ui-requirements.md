# Aibo Rev 默认工作台：界面硬性要求

Status: active（2026-11-10；2026-11-11 改为 MyGO 原生 UI，见 [ADR 0006](../adr/0006-native-ui.md)）

本文是默认界面（F20.1，MyGO 原生 UI）的**可验收约束**。设计背景、取舍理由与示意见 [界面与交互方案](ui-interaction.md)；原型只作示意。

## 0. 使用方式

**优先级。** 本文 > [界面与交互方案](ui-interaction.md) > [设计令牌](tokens/tokens.json)以外的任何数值 > [静态原型](prototype/index.html)、[`prototypes/native-ui`](../../prototypes/native-ui/README.md) 与 [`prototypes/stream-composer`](../../prototypes/stream-composer/README.md)。发现冲突时以本文为准，并把冲突报告给维护者，不得自行选择其中一方继续实现。原型中的示例数据（例如某个 Agent 不支持插话）不构成要求。

**等级。**

| 等级 | 含义 |
| --- | --- |
| 必须 | 不满足即不能合入。确有困难时先提出修改本文，不能在实现中绕过 |
| 不得 | 明确禁止的做法，同样不能合入 |
| 建议 | 默认应当这样做；偏离时须在变更说明中给出理由 |

**验证方式。** 每条要求列出一种或多种：

- `static:<检查名>` — `go -C tools/ui-checks run . static` 中的静态检查（令牌与原生 UI 的 Go 源码）。
- `uitest` — `tools/ui-checks/acceptance` 中 `ID` 为该编号的验收用例，由 MyGO 的无窗口测试器 `ui.Tester` 驱动，按 §11 的测试契约定位元素。
- `perf` — 同上，但只在提供 `history-10k` 夹具的目标上运行。
- `manual` — 需要人工或在真实 MyGO 窗口中验证（输入法、剪贴板、拖放、读屏朗读、平台差异），不能由脚本替代。

`go -C tools/ui-checks run . requirements` 会检查本文：编号唯一、字段齐全、Checklist 编号存在且已勾选、声明的静态检查确实存在、验收用例引用的编号存在，并列出尚无要求覆盖的已勾选 Checklist 项。产品实现成为验收目标之前，尚未编写用例的 `uitest`/`perf` 要求只列为提示；之后配置 `requireAllUITests: true`，缺少用例即失败。运行方法、新增验收目标与例外标记见 [`tools/ui-checks/README.md`](../../tools/ui-checks/README.md)。

**交付门槛。** 合入默认界面的改动前，`go -C tools/ui-checks run . all` 必须全部通过；因目标缺少夹具而跳过的测试不算通过，须在变更说明中列出。`manual` 项由评审者在变更说明中逐条确认。

**范围。** 约束 Aibo 自身的原生界面。2026-11-11 起不再有可替换的外部完整呈现包（[ADR 0006](../adr/0006-native-ui.md)）。能力包的工具面板是包自带的网页，在嵌入的 WebView 中运行，不受本文视觉条款约束；宿主向面板提供 `tokens.css`，建议面板使用。

## 1. 总则

#### UI-GEN-01 · 必须 · 只通过交互层访问业务
- 条款：界面包读取数据、发起操作只经过宿主的交互层（[ADR 0006](../adr/0006-native-ui.md)），不得直接引用运行核心、ACP 连接层或存储的包。
- 依据：ui-interaction §0；ADR 0006
- Checklist：F20.1
- 验收：代码评审确认界面包没有绕过交互层的导入或调用。
- 验证：manual

#### UI-GEN-02 · 不得 · 在界面中推断执行结果
- 条款：界面不得自行解释厂商协议字段，也不得根据计时、按钮点击或文本内容推断“已投递”“已停止”“已暂停”等结果；这些状态只来自核心发布的状态。
- 依据：ui-interaction §1；决议 04、07、08
- Checklist：F04.7、F09.1
- 验收：代码评审确认状态文字与样式只由核心状态映射得到；验收用例中各“请求已发送”状态在核心确认前保持未确认样式。
- 验证：manual

#### UI-GEN-03 · 不得 · 为范围外功能放占位入口
- 条款：不得为未勾选的 Checklist 功能放置“即将推出”“敬请期待”等占位入口或文案。
- 依据：ui-interaction §0
- Checklist：F20.1
- 验收：源码中不出现禁用文案清单中的词。
- 验证：static:forbidden-copy

#### UI-GEN-04 · 必须 · 提供验收接口
- 条款：界面实现必须提供 §11 的验收目标（`acceptance.Target`）与测试契约中的无障碍名称，使本文的验收用例能够运行；夹具只存在于测试代码中，不进入发布构建。
- 依据：本文 §11
- Checklist：F20.1
- 验收：验收套件在实现目标上全部可运行（无因找不到契约元素导致的失败）；未知夹具报错。
- 验证：uitest

## 2. 视觉

#### UI-VIS-01 · 必须 · 使用设计令牌
- 条款：颜色、字体、字号、间距、圆角、层级与动效使用 `docs/design/tokens/tokens.json`（经 `go -C tools/ui-checks run . tokens` 生成的 Go 令牌）。界面代码中不得直接写颜色（`ui.RGB`、`ui.RGBA`、`ui.Hex`、`ui.Color{…}`）；确需例外（例如 Agent 品牌色）时在同一行或上一行注明 `ui-check-allow: color <理由>`。
- 依据：ui-interaction §2
- Checklist：F20.1、F20.3
- 验收：静态检查无硬写颜色；生成的 Go 令牌与 `tokens.css` 与 tokens.json 一致。
- 验证：static:no-hardcoded-color、static:token-sync

#### UI-VIS-02 · 必须 · 对比度
- 条款：tokens.json `contrast.pairs` 中的前景/背景组合在浅色与深色下都达到所列对比度；状态色会用作 12px 文字，按 4.5:1 要求。
- 依据：ui-interaction §2.1、§14
- Checklist：F20.3
- 验收：对比度检查全部通过。
- 验证：static:contrast

#### UI-VIS-03 · 必须 · 浅色与深色完整
- 条款：每个颜色令牌在浅色、深色下都有取值；深色不是浅色的自动反转。
- 依据：ui-interaction §2.1
- Checklist：F20.3
- 验收：令牌完整性检查通过。
- 验证：static:tokens-complete

#### UI-VIS-04 · 不得 · 小于 12px 的文字
- 条款：可读文字的字号不得小于 12（DIP）。纯图形徽记须设为图像角色并给出无障碍名称，或从无障碍树中隐藏，才可例外。
- 依据：ui-interaction §2.2
- Checklist：F20.1
- 验收：源码中 `FontSize` 与主题字号没有小于 12 的字面量，令牌 `font.size-*` 不小于 12px；运行时字号人工抽查。
- 验证：static:min-font-size、manual

#### UI-VIS-05 · 不得 · 左侧信号条
- 条款：卡片、列表项、提示块、引用块不得用一侧加粗的彩色边条（`BorderStartWidth` 宽于 1、`BorderWidth` 左边宽于 1 且与右边不同、`ui/markdown` 的 `QuoteBarWidth` 非 0、贴边的窄竖条元素）表达状态或选中。所用 UI 库或设计系统明确规定时例外，须在同一行或上一行注明 `ui-check-allow: left-accent <出处>`。
- 依据：ui-interaction §2.4
- Checklist：F20.1
- 验收：静态检查没有发现左侧信号条；贴边窄竖条元素在截图中人工核对。
- 验证：static:no-left-accent、manual

#### UI-VIS-06 · 必须 · 可见的焦点
- 条款：键盘焦点必须可见（MyGO 焦点环，宽 2，颜色取主题 `Focus`，即令牌 `accent`）。`FocusRing(false)` 关掉焦点环时必须在同一元素上用 `FocusVisible()` 提供替代样式，并注明 `ui-check-allow: focus-ring <替代样式位置>`；主题的 `FocusRingWidth` 不得小于 2。
- 依据：ui-interaction §14
- Checklist：F20.1
- 验收：静态检查没有未说明的 `FocusRing(false)`。
- 验证：static:focus-ring

#### UI-VIS-07 · 必须 · 状态不只靠颜色
- 条款：状态标记（会话状态点、投递状态、请求状态）必须同时有文字或非空的无障碍名称。
- 依据：ui-interaction §2.3、§14
- Checklist：F20.1
- 验收：会话列表的每个状态标记都有非空的可读名称。
- 验证：uitest

#### UI-VIS-08 · 必须 · 尊重减少动态效果
- 条款：系统开启“减少动态效果”时停用或弱化位移动画。MyGO 的动画默认遵循该设置；用 `NonMotion: true` 绕过它时只能用于不产生位移的效果（如淡入淡出），并注明 `ui-check-allow: motion <理由>`。
- 依据：ui-interaction §1、§14
- Checklist：F20.1
- 验收：静态检查没有未说明的 `NonMotion`；开启减少动态效果后人工核对。
- 验证：static:reduced-motion

#### UI-VIS-09 · 必须 · 玻璃只用于外框层
- 条款：Liquid Glass 材质（窗口材质与 `plugins/glass` 的 `Glass`、`ScrollEdge`、`Blur`）只用于侧栏、标题行下的滚动边缘、浮动输入区及其上的控件，以及后续组件设计明确列出的位置。消息、工具卡、审批卡、结果未知卡、代码块与工具面板区不得使用半透明材质，背景保持不透明令牌色。玻璃上的文字在浅色、深色下与常见内容叠放时都须清晰可读。
- 依据：ui-interaction §2.5；ADR 0007
- Checklist：F20.1
- 验收：深浅色截图中，内容滚到玻璃下方时玻璃上的文字可读，内容层没有透出下层。
- 验证：manual

#### UI-VIS-10 · 必须 · 尊重减少透明度
- 条款：系统开启“减少透明度”时，所有玻璃与窗口材质改为不透明表面，界面不留透明区域；开启“增强对比度”时玻璃边缘可辨。不得绕过 MyGO 对这两项偏好的处理。
- 依据：ui-interaction §2.5、§14；ADR 0007
- Checklist：F20.1
- 验收：以 `ui.Preferences{ReduceTransparency: true}` 与 `HighContrast: true` 截图，并在真实窗口中开启系统设置后人工核对。
- 验证：manual

#### UI-VIS-11 · 必须 · 窗口按钮让位
- 条款：隐藏标题栏的窗口中，标题行必须按 `c.TitleBar()` 留出窗口按钮占用的位置：左侧 `Left`（macOS 交通灯）、右侧 `Right`（Windows 的最小化/最大化/关闭）；最右侧的标题行随工具面板展开与收起变化，都须让出 `Right`。窗口的 `TitleBarHeight` 与标题行同高。标题行中的控件不得与窗口按钮重叠。
- 依据：ui-interaction §2.5、§15
- Checklist：F20.1
- 验收：用 `ui.Tester.SetTitleBar` 模拟 Windows（`Right` 为 138）截图，工具面板展开与收起两种状态下控件不进入窗口按钮区域；Windows 实机复核。
- 验证：manual

#### UI-VIS-12 · 必须 · 弹出层统一且保留标准行为
- 条款：下拉选择、菜单、子菜单、候选列表与浮层使用同一玻璃面板与菜单项样式（ui-interaction §2.5）。自绘外观时必须基于 MyGO 的无外观部件（`SelectBase`、`MenuBase`、`PopoverBase` 等），保留其键盘操作（方向键、Home/End、首字母跳转、Enter/Space、Escape、Tab 关闭）、焦点归还与无障碍角色；不得用普通按钮与面板拼出菜单。
- 依据：ui-interaction §2.5、§13、§14
- Checklist：F20.1
- 验收：键盘打开菜单、移动高亮并选择后菜单关闭、焦点回到触发按钮；读屏识别为菜单与菜单项；深浅色截图人工核对。
- 验证：manual

## 3. 导航与会话目录

#### UI-NAV-01 · 不得 · 独立的关闭会话入口
- 条款：默认界面用会话列表切换，不得提供“关闭会话”入口（包括禁用状态的菜单项）；离开会话不结束执行。
- 依据：ui-interaction §4.2；决议 03、05 Q23
- Checklist：F03.2、F03.3
- 验收：会话行菜单与会话头菜单中没有“关闭”项。
- 验证：uitest

#### UI-NAV-02 · 必须 · 排序与置顶
- 条款：会话默认按最近活动排序；置顶的会话显示在全部工作区分组之上的“置顶”区，不在所属分组中重复，并显示所属工作区名称；仅切换查看不得改变顺序。
- 依据：ui-interaction §4.1、§4.2
- Checklist：F03.2
- 验收：切换到另一个会话后列表顺序不变；置顶某会话后它出现在“置顶”区、离开所属分组；取消置顶后回到所属分组。
- 验证：uitest

#### UI-NAV-03 · 必须 · 有活动时归档先确认
- 条款：归档有活动（回合、目标、后台任务）的会话时，必须先列出这些活动并请用户选择停止后归档或取消；确认停止前不得归档。
- 依据：ui-interaction §4.2；决议 03
- Checklist：F03.5
- 验收：对执行中的会话选择归档 → 出现确认对话框，会话仍在列表中。
- 验证：uitest

#### UI-NAV-04 · 必须 · 会话详情默认隐藏
- 条款：引用授权、用量、适配器与原生会话信息默认不在工作台中展示，必须可从会话菜单打开。
- 依据：ui-interaction §8.3
- Checklist：F08.5
- 验收：初始界面不显示原生会话 ID；从会话头菜单打开“会话详情”后显示。
- 验证：uitest

#### UI-NAV-05 · 必须 · 工具面板区
- 条款：没有能力包提供面板时不显示工具面板区；有面板时默认收起，展开后标明提供它的插件与版本；面板故障不影响会话视图。
- 依据：ui-interaction §8.2；决议 09 修订
- Checklist：F17.1、F17.5
- 验收：初始无展开面板；展开后可见来源说明。
- 验证：uitest


#### UI-NAV-06 · 必须 · 新建会话与 Agent 检查
- 条款：新建会话时列出可用 Agent 及其适配器版本、验证状态、可执行文件与认证检查结果；检查未通过的 Agent 可以选中查看原因，但创建入口不可用。
- 依据：ui-interaction §4.3；决议 04
- Checklist：F03.1、F02.1、F02.3、F02.5、F02.6
- 验收：`Mod+N` 打开新建会话；选中检查未通过的 Agent 后“创建”不可用。
- 验证：uitest

#### UI-NAV-11 · 必须 · 缺少 CLI 或 Node 时的指引
- 条款：Agent 检查发现缺少 CLI 时，显示该 Agent 包提供的安装指引与官方文档链接，Aibo 不代为安装；缺少满足版本要求的 Node 时，提供“选择已有的 Node”与“为 Aibo 下载 Node（最新 LTS）”，下载只在用户操作后开始，显示进度与校验结果，校验失败时不切换。设置中显示当前 Node 的版本与来源（手动选择 / 系统 / Aibo 下载），并提供“更新到最新 LTS”。
- 依据：ui-interaction §12；ADR 0009
- Checklist：F02.6、F02.7
- 验收：`agent-missing-cli` 中显示指引与链接、“创建”不可用；`node-missing` 中两个入口都在，模拟校验失败后仍为原来的 Node。
- 验证：uitest

#### UI-NAV-07 · 必须 · 未验证组合的标识
- 条款：当前会话的 Agent/适配器组合未经验证时，会话头显示“未验证”并说明含义；不得因此禁用全部功能。
- 依据：ui-interaction §5.1；决议 04 Q15
- Checklist：F02.5
- 验收：`untrusted`（其 Agent 为未验证组合）中会话头显示“未验证”。
- 验证：uitest

#### UI-NAV-08 · 必须 · 工作区的添加与移除
- 条款：添加工作区使用系统文件夹选择器并随后确认信任；移除工作区时说明保留业务历史、项目文件与暂停的队列，有活动时先确认停止。
- 依据：ui-interaction §4.2、§12
- Checklist：F01.1、F01.3
- 验收：在 MyGO 构建中验证系统文件夹选择器与移除确认。
- 验证：manual

#### UI-NAV-10 · 必须 · 会话行的常用操作与右键菜单
- 条款：会话行显示 Agent 图标（无障碍名称为 Agent 名称）。悬停或键盘焦点在行内时，行内出现“置顶 / 取消置顶”“归档”（已归档为“取消归档”）按钮，键盘可依次到达；右键、菜单键或 `Shift+F10` 打开的菜单列出全部会话操作：打开、置顶 / 取消置顶、改名、在输入框中引用、复制会话信息、归档 / 取消归档。行内按钮与菜单执行同一操作，规则同 UI-NAV-02、UI-NAV-03。
- 依据：ui-interaction §4.1、§4.2
- Checklist：F03.2、F03.5、F07.1
- 验收：悬停某行 → 出现“置顶”“归档”；点“置顶”后该行移到“置顶”区；右键某行 → 菜单含上述全部操作；会话头不显示“Agent 名称 · 工作区”。
- 验证：uitest

#### UI-NAV-09 · 必须 · 已归档与离线历史可读
- 条款：已归档会话、Agent 不可用的会话都可以阅读与搜索；输入区替换为说明及恢复入口（取消归档、重新安装），不得显示为可发送。
- 依据：ui-interaction §4.2、§11；决议 06 Q34
- Checklist：F10.1、F12.3、F19.7
- 验收：从搜索打开已归档会话 → 显示历史消息与“取消归档后继续”。
- 验证：uitest
## 4. 会话流

#### UI-STREAM-01 · 必须 · 消息排布
- 条款：用户消息为右对齐的聊天气泡；Agent 回复不加气泡、占满正文宽度。
- 依据：ui-interaction §5.2
- Checklist：F04.1、F04.3
- 验收：用户消息右边缘贴近会话流正文区右边缘，左侧留白明显大于右侧。
- 验证：uitest

#### UI-STREAM-02 · 必须 · 投递状态
- 条款：用户消息必须区分并显示“已排队/投递中/已接收/结果未知”；“结果未知”使用 `unknown` 样式，只提供“核实”和“重新发送（可能重复执行）”。
- 依据：ui-interaction §5.2；决议 07
- Checklist：F09.2、F04.8
- 验收：`delivery-unknown` 中存在投递状态为“结果未知”的用户消息，且提供上述两项操作。
- 验证：uitest

#### UI-STREAM-03 · 必须 · 跟随底部

### 11.2 夹具与验收目标

实现提供一个 `acceptance.Target`：`Open(夹具名)` 返回该初始状态下的视图；不认识的名称必须返回错误，已登记但不提供的夹具返回 `acceptance.ErrUnsupported`，对应用例显示为跳过，不算通过。`history-10k` 还须提供 `Stream`，模拟运行核心逐段发布一条长回复。实现在自己的测试中调用 `acceptance.Run(t, target)`，并在 `ui-checks.config.json` 的 `targets` 中登记。夹具只存在于测试代码中。

| 名称 | 初始状态 |
| --- | --- |
| `running-approval` | 当前会话执行中；1 个待审批；队列 1 项；1 个子 Agent 执行中；Agent 不支持插话；输入框有 1 个会话引用 |
| `delivery-unknown` | 当前会话空闲；1 项投递结果未知且队列暂停（共 3 项）；持续目标推进中且支持暂停；1 个后台任务运行中 |
| `pending-question` | 当前会话有 1 个待回答的选择题 |
| `turn-failed` | 当前会话回合失败、队列暂停，含 1 处缺口标示 |
| `untrusted` | 当前会话所在工作区未信任 |
| `idle-empty` | 当前会话为空闲的新会话，无消息、队列、目标与任务 |
| `restart` | 模拟应用重启后：当前会话有失效审批与恢复卡 |
| `save-failure` | 关键保存失败 |
| `history-10k` | 当前会话含 10,000 条历史，并提供 `Stream`（性能验收用） |

当前唯一的验收目标是 [`prototypes/native-ui`](../../prototypes/native-ui/README.md)，只提供 `idle-empty` 与 `history-10k`。
